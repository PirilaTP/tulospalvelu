# 6.2 Support for recreational orienteering

### 6.2 Support for recreational orienteering

For recreational competitions
the program has several operating modes, which are enabled by giving
the program the startup parameter

`KUNTOSUUNNISTUS=x` 

where x is 1, 2 or 3. If "=x" is omitted, the
mode of operation is the same as with the value 1. In addition, for recreational orienteering there is
a startup parameter suitable for registering starters

`ESILUENTA=KUNTO` 

The recreational orienteering mode is then entered by selecting
"Results service/Emit reading" from the main menu.

The parameter values 1 and 2 lead to an operating mode where
the competitor file initially contains no data about the participants; instead their
data is in a separate list of possible participants
(the person database). The competitor file must then contain so
many vacant places that all participants are sure to fit.

The value 3 and `ESILUENTA=KUNTO` lead to a mode where participants
already have a reserved bib number in advance and where the personal data is either ready
in a file or entered separately, for example at the competition office. At the competition office
you can then use the entry window and, if desired, the person database
with it.

When the parameter has been given a value, the program expects
registration as a starter and the punch check to take place at different
readings. When the card is read for the first time, the program marks
the competitor as started and saves the Emit code in the participant's data. When
the Emit card is read for the second time, the result is saved and the
Emit code is changed to a free value from the range of small numbers. Thus the third reading is
again the registration of a new competitor, in exactly the same way as the first
reading. Registration and punch check can take place on the same or different
computers, provided that there is a data connection between the computers.

When the parameter gives the value 2, the program expects
the card to be read only after the performance, in which case both
the participant is determined and the result is given.

Also in operating mode 1 the result can be saved on the same
reading, provided that the punches give an accepted performance for some
course. Otherwise a second reading is needed, and between the readings
some other card must be read.

In the operating mode started with the parameter value 3,
the normal situation is that a record corresponding to the bib number
has been reserved for all participants. In the punch check the result is saved for this
competitor. If the Emit code has then been stored, nothing needs to be done when an
accepted performance is achieved. If the code is not in the file,
the bib number must be entered or the correct competitor record selected with the name search.
The Emit code can be linked to the competitor either when the competitor data is
entered or in a pre-start readout using the parameter `ESILUENTA=KUNTO`. When operating with the parameter
`ESILUENTA=KUNTO`, the option
"Results service/Emit reading" shows limited data. Normally you just read
the card and then enter the competitor's number, which can also be read
from a barcode containing the competitor's number followed by Enter. If
an error occurs in reading, it can be cancelled. If the card is already reserved,
the program asks whether the card is left with its previous holder (who may also be
the same competitor) or released for use by the new participant.

#### 6.2.1 Hiding participants' results from results lists

Recreational orienteering events also have participants who do not want their result shown,
only the fact that they took part. This can be done in two ways:

- By defining a class
  in which results are not calculated and entering the participant in it

  - By giving a participant of another class
    the "acceptance marking" *Exclude*. This marking is stored in the data
    as the letter *X*
    , which appears in some listings and which can be
    used to make the marking when it is made by typing in a text field.

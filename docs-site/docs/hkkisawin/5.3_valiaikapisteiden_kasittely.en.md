# 5.3  Handling split points

### 5.3  Handling split points

#### 5.3.1  Determining the timing point with the file lahdepisteet1.lst

Here and above, the most common file name
lahdepisteet1.lst is used. This name is
however used only in a single-stage competition and in stage 1 of a multi-stage
competition. In later stages the stage number replaces the number 1.

The file lahdepisteet1.lst consists of lines of
the form

```
sarja piste koodit
```

sarja  is the class name or
the word KAIKKI or LOPUT, of which the former refers to all classes and the latter to those classes
not mentioned by name in the file.   
piste  is the sequence number of the split point. Both
the letter M and the value 0
refer to the finish. The letter L (or the value -1) refers to the start: timing data arriving
with this code is stored as the competitor's start time instead of a split point,
but only if the startup parameter PAKOTALAIKA has been given. This
is used e.g. when the start time is read from an RFID reader. The first
reading producing a start time is always accepted; later readings replace it
only within the limits allowed by the PAKOTALAIKARAJA parameter (see Appendix 1).  
koodit is
a list of one or more codes. Several consecutive codes can be expressed
by giving the lowest and highest value separated by a hyphen. The source code value can be
between 1 and 9999. It is advisable to avoid the smallest values in the range
that occurs as the value x of the parameter LUKIJAx.

The file may contain, for example, the lines

```
H21E M 25  
H21E 1 31-36  
H21E 2 41 42 43  
H21E 3 1080  
H21E 4 61 62  
H21E 5 1080  
H21E 6 100
```

The first line indicates that source code 25 directs the time
to the finish time, codes 31-36 to the time of split point 1, etc. Source code 1080 takes
the time on its first occurrence to split 3 and, once split 3 has been recorded, to split
5.

#### 5.3.2  Other settings for determining the split point

When you use the parameter

AIKALUKIJAx=VAINA

or the parameter

VAVUOROT

the program selects as the point the first split that
does not yet have a time, and after the splits the finish. The determination can be restricted
by giving the parameter

VAINVÄLIAJAT

which prohibits giving a time to the finish.

A stricter restriction can be given by using the form
of the parameter

VAVUOROT=sama/ala/ylä

where sama gives in seconds
the time within which a repeated time is assigned to the previous timing point.
ala and ylä
give the lowest and
highest sequence number of the split points included when
selecting the point.

People often punch repeatedly at the same point. Unless
there is another punch in between, this produces only one item of data, but situations
where two punches alternate also often occur. To avoid
extra times from this, the program has by default an upper limit of 10 seconds within which
a second reading is ignored. The parameter sama described above replaces the default value
10.

When the point is determined with the file lahdepisteet1.lst, the parameter VAVUOROT affects operation only through the value sama. The limits ala and ylä
are thus not applied, and selection of the first free point is
used whenever the same source code is repeated for several points, like 1080
in the example above.

Normally the program keeps the result for a given point
when new timing data arrives for the same point. This behaviour
can be overridden with the parameter

UUSINAIKA=n

which means that new timing data arriving within n
seconds of the stored time replaces the earlier one.
If =n is omitted, the
default value of 120 s is used.

Determination based on the parameter VAVUOROT
requires that all split times are recorded. If there is
reason to doubt this and if, on the other hand, it is possible
to estimate within reasonable limits how long competitors take between split points, you can use
a method based on the lower time limits given in the
split point definitions. The program uses the differences between consecutive lower limits
and compares the differences of the defined lower limits with the time
elapsed from the previous split point to the moment of timing.

In sports other than orienteering, the program also makes
the comparison the other way round. If more time has elapsed since the previous recorded split
than the sum of the lower limits of two consecutive time differences,
the program skips one split point, and if the difference exceeds the sum of the lower limits
of three time differences, the program skips two split points.
The programs can be made to behave as defined for orienteering by giving the parameter VAINALARAJAT,
and in orienteering to behave as described in this paragraph
by giving the parameter VAINALARAJAT= EI.

# 13.4 Importing course data from a file

### 13.4 Importing course data from a file

The functions of the course data form are almost
completely the same in the relay as in the individual competition. When interpreting the following instructions
you must bear in mind that the individual competition program looks for
the course matching the class name when no individual course has been defined for the competitor,
whereas in the relay an individually defined
forking course is the only option in use during the competition.

The program's own file format closely resembles the IOF
standard 2.0.3 file format, but is not exactly the same. Data saved in the program's own
format can be read using a menu option or
buttons. The button on the tab *Transfer files*
must also be used when reading the program's own file format if data are being added
from another file to data already loaded for handling.

The program can read course data from files produced by several different
course planning programs, such as

- XML files conforming to the IOF definitions (version 2.0.3 and version
  3.0)

  - earlier file formats of the OCAD
    programs.

Some additional selections may be needed, especially
when reading IOF standard 2.0.3 files produced by course planning
programs.

#### 13.4.1 Files based on IOF standard version 3.0

This file format came into use in 2013;
earlier course planning programs do not know this version.

When reading version 3.0 files no selections need
to be made before reading, but after reading the program may state
*The course data include course assignments
to classes* and ask you to choose from the options

- *Keep course names and
  link to classes*. This option thus keeps the course names and produces
  course assignments to classes, shown on the tab *Classes*.

  - *Use own course for
    each class* . This option leads to the course being duplicated for each class
    linked to it and named according to the class names. The original course
    name is no longer used.

    - *Ignore
      assignments* . In this option the assignment data
      are not kept.

This question appears when the classes using each course have been
defined separately during course planning.

#### 13.4.2 Files based on IOF standard version 2.0.3

Files made with Condes typically
contain the course name in the field *Course name*
(CourseName ). With
OCAD all alternatives commonly occur, as well as
practices that the program cannot interpret correctly.

Because the programs offer their users alternative
ways of recording course names, the program allows you to make
choices about this. When the XML file is read on the sub-page *Transfer files,* the program can use the course identifier
saved as the course name or class name and transfer it, according to
the program's needs, to be the name of the course variation. If several classes have been
defined for the same course in repeated ClassShortName fields as the class short name,
the program makes a separate copy of the course for each class.

When all courses are named according to class names, the
recommended procedure is to save the class names in the field *Class short name*, repeating this field for each
class. In this way the original file can contain the course only once, while
the new file the program creates from it contains courses for each class. Course variations
are the natural object of naming when forking courses are used.

The XML file often also contains the punch codes of the controls,
and it is possible to read these together with the courses.

Changes to the timing method are made after the import
on the course data tab.

More courses and codes can be added to the courses and punch codes already visible
in the program by reading a new file on the tab discussed
here. When the course variation name has been selected as the identifier,
data in the program's own format can be read.

The program understands course names of the following type:

In the area <Course>:

<CourseName>H21</CourseName> is recognised as the course name.

<ClassShortName>H65AL</ClassShortName>
is recognised as the class short name. There can be several of these for the same
course, in which case the program creates a separate identical course from each for its own
use.

In the area <CourseVariation>:

<Name>H21</Name> is recognised as the course variation name.

The program can also form the name by combining the course
name and the course variation name.

The program handles only numeric control codes, whose
largest permitted value is 899. When reading a transfer file the program changes the codes
RR1, RR2, etc. into codes 881, 882 etc. (this also applies to the codes RR10-RR19,
which become codes 890-899).

If a letter code other than an
RR control or the letter 'V', 'J' or 'P' occurs in the middle of a course, the program interprets it as
a point related to a marked route or a map exchange, where there is no punching, and skips
this point. In this case the program adds together the distances from the previous control to this
point and from this point to the next point. Using this
feature it is possible to increase the length of a leg between controls even if there is no actual
marked route.

The letters 'V', 'J' and 'P' are used when the control
punching order is partly free to choose (chapter
13.8).

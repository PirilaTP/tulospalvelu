# 5.3  Chip-based timing

### 5.3  Chip-based timing

Chip-based timing is most widely used
in orienteering, where the chip can be an Emit card or an emiTag. emiTag is also suitable
for use in skiing and other sports. The chip can also be an
RFID tag when suitable RFID equipment is available. The following
mainly discusses timing based on the Emit card; use of the program is
largely identical when using emiTag devices.

Using the Emit card for timing requires a so-called
online reader unit, which detects the punch but does not cause the card's clock
to stop, unlike the reader unit used at punch checking. The data
from the reader unit to the results program can travel by many different routes:

1. directly through a serial port

   - in addition to the option above, relaying the serial traffic
     wirelessly using radio modems

     - using the TCP or UDP protocol from a terminal server
       to whose serial port the reader unit is connected

       - using Sune Johansson's SjBoxes, between which
         the serial traffic runs over a current loop

         - using the same data transfer protocol as the
           communication between program instances. This usually uses
           the UDP protocol, but the TCP protocol is also available
           (the message format is defined for communication with my program SendECodes)

           - with emiTag devices the data can also travel through Emit's internet server

In the first four cases the data transfer
is assumed to be fast and the time is taken from the computer clock when the identifying
data have been received. Usually the only data obtained is the Emit code of the card read, but
with SjBox the source code defined for the serial port to which
the reading reader unit is connected is also obtained. In options 5 and 6, in addition to the code,
the moment of reading and a source code indicating the reading point are obtained. In options 1-3
a source code can be attached to the data based on the serial port or other
interface the data arrive through; in the case of a terminal server,
the port number of the terminal server is available for this.

In options 1-4 the parameter LUKIJA must be added
to the program's configuration file for each direct
serial port connection and for each terminal server serial port whose data are
received. When the connection is to the computer's serial port, the parameter has the form

LUKIJAx=y

where x is the connection number and
y indicates that the serial port used is COMy. An SjBox
is connected in exactly the same way as a plain reader in this respect.

For a terminal server using the TCP protocol the corresponding parameter is

LUKIJAx=TCP:ip-osoite:portti

where ip-osoite is the
IP address of the terminal server and portti is the IP port corresponding to the serial port
used (in terminal servers each serial port corresponds to a different IP port).

For timing use, each LUKIJA parameter must be accompanied by the parameter

AIKALUKIJAx=VAINz

or

AIKALUKIJAx=LÄHDEw

In both cases the value x must be the same as in the parameter LUKIJA.
x can, however, be left out, in which case the parameter applies to all LUKIJAx parameters.

The z following the word VAIN can be

- a numeric value 0, 1, 2, ..
  up to the highest split point sequence number in use. The value 0 refers to the finish. A parameter given in this way determines the point to which the time is recorded

  - the letter A, in which case the program
    looks for the first split point that does not yet have a time and records the time for this point

    - the character z can be missing,
      in which case the program uses the file lahdepisteet1.lst
      to select the point. This is suitable mainly for the case where an SjBox is used

In the latter option w
is a numeric value given as the source code of this connection. After this
the program looks up the point using the file lahdepisteet1.lst.

Option 5 is enabled by defining the data transfer
connection concerned in the same way as other data transfer connections. The connection must be defined
as incoming only. In addition, the following parameter must be given (without
this parameter the program ignores messages coming from timing)

YHTEYSAJAT

In this case the program tries to use the file
lahdepisteet1.lst to determine the point, using the
source code that arrives as part of the timing message.

Option 6 is not discussed further here. Instructions
for it are available separately. Note, however, that the file lahdepisteet1.lst
is used for deducing the point in this case as well.

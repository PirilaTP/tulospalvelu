# 9.2 File output

### 9.2 File output

Files can be written using either the UTF-8
(Unicode) character set or the more traditional Ansi/ISO-8859-1/Windows character set.
Which works better depends on the intended use. The file structure can be

- A text file with separated fields (CSV-type
  file).

  - A text file with aligned fields, i.e. with
    the gaps filled with spaces.

    - A text file using continuous text, where
      each class is written without line breaks, but there are line breaks
      between classes. The **press** often wants results
      in this form.

      - As an HTML file

        - As an XML file, both according to the IOF standard V3.0
          and in the program's own format. The program's own format is suitable for use
          in Reittihärveli and in split time analyses that have been prepared
          for it.

          - Results for the FIS and WRE services are obtained
            in the XML format required by these services.

            - WebScorer-format start lists are suitable for
              WebScorer's tracking service (used e.g. by coaches
              in skiing competitions).

              - Pursuit starts for clocks produces a simplified
                file suitable for transfer to a start clock using, for example,
                my program ASC3Control (see [chapter 9.5](9.5_lahtoluettelot.md)
                ).

#### 9.2.1 File outputs for the Finnish Orienteering Federation (SSL) and the Finnish Ski Association

The results are written in the results service mode of the competition stage to be output,
on the form of the option Outputs. The file name is defined
as for other file outputs. As the file type select SSL results delivery format or SHL results delivery
format; the program selects ISO-8859-1 as the character set. Classes are selected in the normal
way. Other options do not need to be changed unless a narrower selection is wanted.

In the case of a skiing competition,
the program asks, when output starts, for the competition code and, for each class, the distance and technique.
The program picks the distance and technique from the distance field of the class data, where
the technique must be the last (or last two) characters and the distance
before it in kilometres with at least one decimal, according to the instructions of the Finnish Ski Association
(see [chapter
2.2.3](2.2.3_matka_ja_hiihtotapa_hiihtokilpailussa.md)
). The presentation of the classes is however easy to correct when writing the file.

The Finnish Ski Association results file can also be written
using class combinations, if this produces a result better suited
for submission.

#### 9.2.2 Additional features of HTML outputs

The appearance of HTML outputs can be adjusted quite
extensively on the relevant formatting settings page ([chapter
9.3.1](9.3.1_html-lisamaaritykset.md)
).  In HTML results lists
formatting controlled by a separate CSS file can also
be used. The name of the formatting file used is then tuloslue.css.
The available codes can be found by making a sample output using
the program's internal CSS formatting, which also provides a template for creating
your own file.

The appearance of the output can be adjusted even more extensively
by using the XML output written by the program and an XSL file
controlling its use.

The program defines two alternatives
for HTML outputs: a normal HTML output and an output intended for mobile
devices. Both can be formatted equally extensively, so
the simplicity of the mobile output only concerns the default formatting values.

Text and also images can be added below the main title
of both results and start lists. Adding text does not require
the use of HTML commands, but HTML commands can also be added among the text,
with which you can format text, add links to images
or other HTML documents and implement many other possibilities
offered by the HTML language. The program opens an editing window when the field *Add
text below the title* is ticked.
At the same time you also select a possible earlier file from which text
is taken and specify a new file in which the edited text is saved for
use. The program leaves everything else unchanged but replaces line breaks with the HTML codes <p> and
<br>.

The third tickable field lets you see
immediately what the HTML output produced looks like.

#### 9.2.3 Orienteering WRE competitions

Results from WRE competitions are sent as an XML file
in IOF standard format. The competitor data must contain in the field Intl. id the
id codes issued by the IOF. (The practice changed at the beginning of 2014). Getting the
results in the correct format requires that the competition date has been entered
through the competition basic data form in the stage-specific additional data in the form
yyyy-mm-dd.

#### 9.2.4 XML file outputs from FIS competitions, FIS points

Before producing results in the FIS file format you must
make sure that

- the FIS codes of all competitors have been entered
  in the field Intl. id. The program normally reads the codes from the KILMO
  entry data, but any gaps must be filled in
  manually

  - the valid FIS points have been stored
    in the competitor data in the ranking points field (points field 3)

    - the competitors' names are in the form used in the FIS
      database

      - the name of the class or class combination to be output begins
        with the letter N, L, W or D when it is a women's class. The name of a men's class
        must not begin with any of these
        letters.

The required data can be found on the FIS website under *FIS points
lists*, from where
you must fetch the latest cross-country *Full list*. The name of this
file is of the type CCFP615F.zip (in this example it is the 6th list of the 2015
season). The program needs two of the files contained in this zip file,
whose names in this example are CC615com.csv and
CC615pts.csv. The latest versions of these two files must be made
available, for example in the competition directory. The FIS points can now be fetched
with the program option *Entries / Read FIS files*.

The program allows you to add competitors
with the option *Entries* so that the names and (distance)
points are stored directly in the data. This is however a rarely used
method. There is more information on this in [chapter 3.1](3.1_ilmoittautumisten_syotto.md).

The points must be read before producing the FIS results file
(reading can be done before or after the competition). Before writing the results
it is also advisable to transfer the names to the competition data, so that they are
spelled as FIS expects. It is not advisable to fetch the names into a file
that is used in other contexts, nor usually before the competition, because the FIS
spelling does not match Finnish practice. The points must be transferred separately
for sprint competitions and other competitions by selecting the discipline correctly. The program gives
everyone without FIS points the points 9999,999
so that they cannot disturb the determination of the competition's penalty points. (The points are stored
multiplied by a thousand, so that they are represented as integers.)

Before output you must also prepare a text file describing the competition,
whose content is of the following type:

```
Fvalue=800
Minpenalty=15
Fislist=2
Season=2012
Codex=2293
Nation=FIN
Discipline=5K
Category=FIS
Date=13.11.2011
Eventname=Muonio
Place=Muonio
TDidcode=0
TDlastname=Toerni
TDfirstname=Pertti
TDnation=FIN
Variable
```

From this file the program gets the additional data needed for the results file.
The data in the file should be understandable to anyone who
knows the FIS rules for results.

When all preparations have been made, output is done
in the same way as output of the SHL file, except that the definition file described above
must be selected before starting the output. From the point of view of FIS results,
each class is often a competition of its own, so the corresponding
files are made one at a time. The resulting XML file contains
the penalty value calculated for the competition and each competitor's points and other
required data in the form required by FIS. It is essential that the results
have been calculated with the precision FIS expects. Otherwise FIS does not accept
the file, the problems concerning the last decimals of the points and ties.

From sprint competitions two sets of results are submitted to the FIS system,
one from the qualification and the other according to the final
ranking. For the qualification you proceed in the same
way as in distance competitions. The results taking all sprint stages into account
are submitted without times (i.e. as placings only), and FIS does not calculate
points from them. For the final results Fvalue=0, from which
the program knows that times are not written and points are not calculated.

Both sprint FIS files are made with the program
operating in the results service mode of stage 1 and selecting the class as the qualification
class. When producing the qualification results, select as the stage *This stage
result*, and for the overall results *Overall positions.* In addition
you must select the definition file corresponding to the file to be produced. For
the file based on overall positions to be formed correctly, all the formations of the different stages
must have been gone through with the program option *Ski sprint transfers* , because the program may
otherwise work incorrectly when determining the overall placings. E.g. missing or excess
Q/q markings for advancing from the qualification can lead to errors.

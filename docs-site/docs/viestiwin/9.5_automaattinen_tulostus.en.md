# 9.5  Automatic output

### 9.5  Automatic output

Both printer and file output can be started
as automatic. This can be done either with parameters or
through the menus of the output functions while the program is running.

#### 9.5.1 Automatic output of HTML files

In a relay, automatic output should usually be
arranged so that the results of each leg are written to their own file,
and any split points also each to their own file. This can be
done with the help of the file autofile.lst,
which lists all the points to be output. Each line of the file
is of the form

```
sarja osuus  piste
```

where changeover/finish is indicated by point number 0.

The program adds the suffix \_sarja\_osuus\_piste.html (class, leg, point)
to the base name of the HTML files created.

The base name tied.nimi of the file can be given with the parameter

```
html=tied.nimi/tulostusväli
```

where tied.nimi may also include a directory path and tulostusväli (output interval)
is given in seconds. This parameter
also starts automatic output immediately when the program starts.
Directing the automatic output into its own folder with the directory path
makes things clearer.

#### 9.5.2  Transferring files to a server

When an HTML file has been written, it can be sent automatically
to a web server with an external command file. After
output, the program runs the command defined with the parameter

```
KOMENTO=komentotiedosto
```

The command must work without user intervention
and must not write to the screen (stdout is automatically redirected
out of sight).

Earlier versions of the program also had built-in FTP/SFTP transfer,
which was defined on the *File server settings* form and
saved in the file `AutoJakelu.xml`, together with the corresponding
`AUTOJAKELU` startup parameter. This feature has been removed (it required
a commercial add-on) and is now replaced by this `KOMENTO=` route.

##### Recommended implementation: rsync + SSH

A modern and secure way to transfer the results files is `rsync`
over an SSH connection. `rsync` transfers only changed files, and the
`--delay-updates` flag renames the individual files from temporary names
to their final names only at the end of the transfer. This way viewers normally
do not see a half-finished HTML file. SSH public key authentication replaces
the password, so the transfer is suitable for automatic runs.

Prerequisites: Windows 10/11, WSL2 + Ubuntu (install with `wsl --install`
in PowerShell as administrator) and SSH access to the target server.

Create a key and copy it to the server from the WSL terminal:

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519_kisa
ssh-copy-id -i ~/.ssh/id_ed25519_kisa.pub user@kisapalvelin.fi
```

The passphrase must be left empty so that the transfer succeeds without
user action.

Create the command file that the results software runs. Save it
somewhere other than the HTML directory being published, e.g. as
`C:\kisa\siirto\siirto.cmd`:

```cmd
@echo off
set LOG=C:\kisa\siirto\siirto.log

wsl -- rsync -a --delete-after --delay-updates ^
  -e "ssh -i /home/KÄYTTÄJÄ/.ssh/id_ed25519_kisa -o StrictHostKeyChecking=accept-new -o ConnectTimeout=10" ^
  /mnt/c/kisa/www/ ^
  user@kisapalvelin.fi:/var/www/html/kisa/ ^
  >> "%LOG%" 2>&1

exit /b %ERRORLEVEL%
```

The Windows path `C:\kisa\www\` appears in WSL as `/mnt/c/kisa/www/`.
`ConnectTimeout=10` prevents the command from hanging when the network
goes down. Keep `siirto.cmd` and `siirto.log` in a different directory from
the HTML files being published, so that they are not mirrored to the server.

Connect the command to the results software in the configuration file:

```
HTML=c:\kisa\www\tulokset.htm/60/S
KOMENTO=c:\kisa\siirto\siirto.cmd
```

If WSL cannot be installed, the same can be done with Windows' own OpenSSH client
and a separately installed rsync package (cwRsync, MSYS2). In that case
`rsync.exe` is called directly and the paths are in Windows format.

# 3.2 Reading entries from a file

### 3.2 Reading entries from a file

#### 3.2.1 Import from the orienteering and skiing entry systems

The program supports importing entries from files produced by the orienteering
IRMA system and the skiing Kilmo system. A file in a supported
format can be read with the option *Entries / Get from file* by selecting *Orienteering entry file* or *Skiing Kilmo entry file*. The program then
asks you to select the file and starts reading it.

Previously read data can be updated by reading
the entry data again. If both the file and the program's earlier
data contain the teams' (bib) numbers, the program uses this number
to decide which data concern the same team. If the number is not present
in both data sets, the program compares the combination class-club-team, where
team means the club's first, second etc. team.

When the data are read from a file produced by Kilmo,
each team gets the number Kilmo uses to identify it. These
numbers can be replaced with new ones on the form *Numbering and
start times* or *Transfer additional data* in the way
described in chapter [4.1](4.1_lahtoajat_ja_kilpailijanumerot.md)
.

#### 3.2.2 Import from a csv file and from data created with Excel

Both entry data and
other data can be imported into the program from a csv file. Two basic models are available for this

- Creating new teams from the data in the csv file
  - This option works both without and with running orders.- The import can be done either assigning
      bib numbers at the same time or leaving the bib numbering to be done in the program.- Adding or changing data for teams already saved
    - This option can be used, among other things, to import running orders and forking codes.- In this option the team is identified by its
        bib number, so the option is available only once the teams have been numbered.

The csv file must be prepared so that the first row
gives the content of each column with a header code and the other rows contain the data
of each team. Each team corresponds to one row, so all data for the different
legs are on the same row. Once a team has been created, it is
also possible to add data one leg at a time. When transferring all
possible data, the header row of a file for 4 legs and 2 split times looks like this:

Note that the field *Selitys* (explanation) overlaps
with the leg-specific points fields. The first 12 characters
are stored as numeric values in the points fields and only the last two characters
in the column *Selitys*
.
Thus the explanation text is normally not readable in the csv file, but it is restored as text when the file is read back.

"No";"Rata-1";"Rata-2";"Rata-3";"Rata-4"

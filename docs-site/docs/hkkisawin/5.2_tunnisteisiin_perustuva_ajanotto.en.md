# 5.2  Chip-based timing

### 5.2  Chip-based timing

Chip-based timing is most widely used
in orienteering, where the chip can be an Emit card or an emiTag. emiTag is also suitable
for skiing and other sports. The chip can also be an
RFID tag when suitable RFID equipment is available. The following
mainly covers timing based on Emit cards; using the program is largely identical
with emiTag devices (see [appendix 9](liite_9._emitag-laitteiden_kaytto.md)).

Using an Emit card for timing requires a so-called
online reader unit, which detects the punch but does not stop the card's
clock, unlike the reader unit used in punch checking. The data
from the reader unit can reach the results software in many different ways:

1. directly through a serial port

   - adding to the above option wireless transmission of
     the serial traffic using radio modems

     - using the TCP or UDP protocol from a terminal server
       to whose serial port the reader unit is connected

       - using Sune Johansson's SjBoxes, between which the
         serial traffic runs over a current loop

         - using the same data transfer protocol as
           the communication between program instances. This usually uses
           the UDP protocol, but the TCP protocol is also available
           (the message format has been defined for communicating with my program SendECodes)

           - with emiTag devices the data can also travel via Emit's web server

In the first four cases the data
transfer is assumed to be fast, and the time is taken from the computer clock when the identifying
data has been received. Usually the only data available is the Emit code of the card read, but
with an SjBox you also get the source code defined for the serial port to which
the reader unit that made the reading is connected. In options 5 and 6 you get, in addition to the code,
the reading time and a source code identifying the reading point. In options 1-3
a source code can be attached to the data based on the serial port or other
connection through which the data arrives; for a terminal server
the terminal server's port number can be used for this.

In options 1-4 the parameter LUKIJA must be added to the program's configuration file
for each direct
serial port connection and for each terminal server serial port whose data is
received. When the connection is to the computer's serial port, the parameter has the form

LUKIJAx=y

where x is the connection number and
y indicates that the serial port used is COMy. An SjBox
is connected in this respect in exactly the same way as a plain reader.

For a terminal server using the TCP protocol, the corresponding parameter is

LUKIJAx=TCP:ip-osoite:portti

where ip-osoite is
the terminal server's IP address and portti is the IP port corresponding to
the serial port used (in terminal servers each serial port corresponds to a different IP port).

For timing use, each LUKIJA parameter must be accompanied by the parameter

AIKALUKIJAx=VAINz

or

AIKALUKIJAx=LÄHDEw

In both cases the value x must be the same as in the parameter LUKIJA.
x can however be omitted, in which case the parameter applies to all LUKIJAx parameters.

The z following the word VAIN can be

- a numeric value 0, 1, 2, ..
  up to the highest sequence number of a split point in use. The value 0 refers to the finish. A parameter given this way determines the point for which the time is recorded

  - the letter A, in which case the program
    finds the first split point that does not yet have a time and records the time for that point

    - the character z can be omitted,
      in which case the program uses the file lahdepisteet1.lst
      to select the point. This is mainly suitable when an SjBox is used

In the latter alternative w
is a numeric value given as the source code of this connection. The
program then determines the point using the file lahdepisteet1.lst.

Option 5 is enabled by defining the
data connection in the same way as other data connections. The connection must be defined
as incoming only. In addition the following parameter must be given (without
this parameter the program ignores messages coming from timing)

YHTEYSAJAT

In this case the program tries to use the file
lahdepisteet1.lst to determine the point, using the
source code that arrives as part of the timing message.

Option 6 is not covered further here. Instructions for it
are in [appendix 9](liite_9._emitag-laitteiden_kaytto.md).
Note, however, that the file lahdepisteet1.lst is used
to determine the point in this case too.

#### RFID tags

The program can also process data from certain
devices based on RFID tags. Currently only support for Sirit devices and
Motorola devices compatible with them is in active use. The details of this system are not
covered in these instructions.

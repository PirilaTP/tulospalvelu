# 6.1 Using the punch check form

### 6.1 Using the punch check form

Performing the punch check requires that
the card reader is connected to the computer and the connection method is given to the program
with a parameter, usually of the form

LUKIJAx=y

where x is the reader number
for the program and can also be omitted. The numeric value y is
the serial port number, which for the computer's own serial port is most often 1,
but for a converter connected to a USB port usually larger, e.g. 5.
The port number can be found in the computer's Device Manager list under
*Ports* .

The punch check also requires that the program
has the course data and the punching unit data of the controls (chapter 13 of these instructions).

When the above requirements are met,
you can go to the punch check with the option *Results service /
Emit reading.* This form shows one competitor's punches and
data about the performance. When the performance is error-free, the data
according to the choices made is saved automatically and shown immediately on this form.
For an error-free performance the background colour of the form is white.
The form can also contain rows with a grey background, which however
do not form part of the performance but typically represent the clearing of the card
before the performance and extra punches during the competition that do not belong to the course.

A new punch reading is processed fully and shown only
if the form has been moved to the latest data. Otherwise a button
appears on the form; clicking it takes you to the processing. The scroll bar
above the punch table lets you browse
earlier punch data. It can also be found with the button *Find participant*.

When the performance is not error-free, the table shows
various background colours and a disqualification proposal is made for the competitor. Under
*Check* you must then select the option corresponding to the performance (e.g.
*DQ*) and save the changes. In some cases the program does not
calculate the result, but calculation becomes possible while the data is
being processed. The result can then be determined with the button *Calculate result
from punches.*

On the punch check form you can also change
the competitor's class or course code. Changing the course is immediately reflected in the
interpretation of the punches. Other competitor data shown on the form can also be changed.

If no competitor has the code of the card read,
the program attaches the data to a vacant record for the duration of the processing
(the program adds the record if no such record exists in advance). An auxiliary form
then appears automatically, on which you specify the competitor to whom the punches
belong. With the button *Change competitor or edit punch data*
the same auxiliary form can be opened when the punches have been recorded
for the wrong competitor. With the auxiliary form the punches can be moved to the correct
competitor, and it can also be used to swap the punch data of two competitors.
The auxiliary form also has a second sub-page on which you can edit data concerning the punches.

Through the form's menus and the buttons at the bottom you can, among other things,

- find the course matching the punches. The program
  reports only one class or course, even if the punches match equally well
  several courses. For a course to be reported, the punches must produce
  an accepted performance. Of suitable courses of different lengths, the program
  selects the one with the most controls and, of those with the same
  number of controls, the first in order.

  - take changed course data into use, which
    requires that the new defining files have been placed in the competition folder
    before this,

    - influence to some extent the data shown and print the punch data
      or control split times on a printer, or

      - start automatic printing of punch data
        containing errors.

        - choose the punch report to be printed
          to fit on narrow paper

          - change the form's operating mode in recreational competitions,
            where some computers handle entries and
            some handle finish tasks

            - choose whether the program verifies error-free reading of the Emit card
              by reading the data twice

              - choose whether the result of the punch check is shown on a very simplified form
                intended for the competitor.

# 6.2 Changes to punches and changing the participant linked to them

### 6.2 Changes to punches and changing the participant linked to them

The participant linked to Emit punches can be changed
on the form *Emit changes*, which can be opened with the
punch check form button *Change competitor or edit
punch data*. The same form can also be used to make changes to the
data read from the card and to the stored readout moment. Changes
to the punch data itself, however, are made in the table of the form *Emit data*,
once this has been enabled through the changes form.

The form *Emit changes* also opens
automatically when a card is read that has an unknown code or that works
faultily, giving code 200, which is typical of faulty cards.

#### 6.2.1 Changing the participant linked to a card

When the participant's bib number is known, the
punch data can be transferred to them simply by entering the number and accepting it. After
the number is entered, the name is shown. In addition, the box *Corresponding
card read* is ticked if punches have already been recorded for that competitor, which
should be taken into account in further actions. (The program also points this out if
you proceed with saving regardless and gives you the opportunity to cancel
the save.) If the competitor's number is not known, you can allow a name search,
type the beginning of the name and complete the search by browsing with the buttons.

In a situation where the cards of two competitors
have been swapped and this is noticed after both have been read, the
error can be corrected by making use of some leg for which no code or data
has been recorded (typically a leg that did not start). You then

- fetch one of the competitors to the form *Emit data*,

  - open the form *Emit changes*,

    - move the data to the free leg and save

      - fetch the other one of the swap to the form Emit data

        - move the data to the leg whose data was moved
          aside above, and save

          - fetch the data moved aside to the form
            Emit data and move it to its correct leg

The selection *Mark card as skipped* means that the data of that card can no longer
be viewed in HkKisaWin or HkMaali. It can, however, be brought back
after the competition with the program EmitEditor.

#### 6.2.2 Changes to punch data

On the second page of the form *Emit changes*
you can change the readout moment recorded for the card. This affects
the split times calculated in orienteering competitions, because the program determines the time of each
punch by comparing the times the card stored at the punching moments with the
readout moment.

One rather common cause of incorrect split times is
that reading the card at the punch check did not succeed on the first attempt,
combined with the fact that the readout moment information left on the card is generally based on the
first readout attempt. This is most clearly true for old cards without a display;
cards with a display and the newest cards without a display behave
differently, but with all of them errors affecting the split times can
occur. If the final results have been obtained correctly at the finish line, the split times
can be corrected with the button *Set the readout moment so that the
finish time definitions are consistent.*

The correction mentioned in the previous paragraph is usually not
correct when the readout moment is too early relative to the finish; in that case
you should carefully find out whether the error is in the readout moment or only in the final result, and
make corrections only
then.

Occasionally it has been found that a card's clock has run
at double speed because of a small short circuit in the card. This
shows in the punch data in that all leg times between controls are
doubled and the first controls typically appear to have been visited
before the competitor's start time. This error can be removed with the button
*Halve card times*
.

Sometimes it is necessary to change a time or a code shown in the punch data,
or make other similar changes to the data. This can be done
on the form *Emit data,* when changes in the table have been allowed
by ticking the relevant
box.

The effects of all the changes mentioned above can be
examined before they are made permanent. They take effect only when
the button *Save changes.* has been used.

#### 6.6.3 Searching for deviations in split times

The button *Find
participant* on the form *Emit data* opens a search function in which you can select
*Finish-last ctrl* as the search criterion. When this selection is made for the first time, the
program moves to the punch data of the approved competitor in which the deviation is
most negative, i.e. in which the final result is probably correct
and the split times are most wrong in the direction that a failed
first readout at the punch check leads to. This error can usually be
corrected as described above in section 6.6.2. You should, however,
examine the data more closely to make sure that the explanation is correct and that the correction
therefore leads to the correct result.

You can then browse the records by searching for the next one and
correct clearly negative deviations to zero. When the difference shown is between
-2 .. 2, it is usually only a matter of deviations due to rounding and perhaps a slight difference
between clocks; removing them is unnecessary and does not necessarily
make the data more accurate than the original.

Next you can enter a clearly
positive number as the search value (typically a number between 3 and 5 is suitable, unless there has been a significant
difference between the clocks). The program then moves on to show
errors in the opposite direction, which are rarer and have
varying causes. They should not be corrected without examining their causes more closely, because
doing so may lose information that would be needed to make the correct correction.

When the largest positive deviations of the approved data
have been gone through, the program shows records related to disqualified and
did-not-finish competitors, whose calculated deviations are often large because of a missing
punch.

#### 6.6.4 Separately sending a record not sent earlier

In some cases there may be Emit records that
are not sent automatically when they are created, but which you want to send
later. This can happen when a record cannot immediately be linked to a competitor
but is skipped, and is later linked to a competitor. Such a record
is not sent automatically to data transfer when it is linked to the competitor,
but sending can be done by requesting it separately
from the menu selection *Functions* of the punch check form.

A similar situation can occur in fitness orienteering,
where one computer is normally used only to register starters, but
is also used to read some finisher. In such an event there is no point in
continuously transferring the data of participants registered as starters to another
computer, but the finisher's data should be transferred for the control split time printouts.
In that case you can give the starter registration computer the parameter

LÄHEMITx=V

and the computer registering finishers the parameter

LÄHEMITy=I

(x and y are the connection numbers).

When these parameters are used, the finish computer does not send
any Emit data to data transfer, and the start computer sends only the data whose
sending is requested through the punch check form's
menu.

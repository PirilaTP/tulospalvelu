# 13.4 Importing course data from a file

### 13.4 Importing course data from a file

The program's own file format closely resembles the file format of the IOF
standard 2.0.3, but is not exactly the same. Data saved in the program's own
format can be read using a menu command or
buttons. The button on the tab *Transfer files*
must also be used when reading the program's own file format if
data from another file is added to data that has already been
loaded.

The program can read course data from files produced by several different
course planning programs, such as

- XML files conforming to the IOF definitions (version 2.0.3 and version 3.0)

  - earlier file formats of the OCAD programs.

Some additional selections may need to be made, especially when reading
files conforming to IOF standard 2.0.3 produced by course planning programs.

#### 13.4.1 Files based on IOF standard version 3.0

This file format came into use in 2013;
earlier course planning programs do not know this version.

When reading version 3.0 files, no selections need to be made before
reading, but once reading has finished the program may state
 *Course data contains
course assignments to classes*
and ask you to choose between the options

- *Keep course names and link to classes*.
  This option thus keeps the course names and produces course assignments to classes
  that are shown on the tab
  *Classes*
  .

  - *Use own course for each class*
    . This option duplicates the course for each
    class linked to it and names the copies according to the class names. The original
    course name is no longer used.

    - *Ignore assignments*
      . In this
      option the assignment data is not kept.

This question
appears when the classes using each course have been defined separately
in connection with course planning.

#### 13.4.2 Files based on IOF standard version 2.0.3

Files made with Condes typically
contain the course name in the field *Course name* (CourseName
). When OCAD
is used, all options commonly occur, as well as
practices that the program cannot
interpret correctly.

Because these programs offer their users
alternative ways of recording course names, the program lets you
make choices concerning this. When an XML file is read on the sub-page *Transfer files,* the program can use the course
identifier stored as the course name or class name and move it, as the
program requires, to be the name of the course variation. If several classes
have been defined for the same course in repeated ClassShortName fields
as the class short name, the program makes a separate
copy of the course for each class.

When all courses have been named according to class names, the
recommended procedure is to store the class names in the field *Class
short name* 
repeating this field for each class. This way
the original file can contain the course only once, while the new
file created from it by the program contains the courses for every class. Course variations are the natural target of naming
when forked courses are used.

The XML file often also contains the punching unit codes of the controls,
and they can be read together with the courses.

Changes to the timing method are made after the import
on the course data tab.

More courses and codes can be added to the courses and punching unit codes already shown in the program
by reading a new file on the tab
described here. When the course variation name has been selected as the identifier,
data in the program's own format can be read.

The program understands course names of the following types:

In the area <Course>:

<CourseName>H21</CourseName> is recognised as the course name.

<ClassShortName>H65AL</ClassShortName>
is recognised as the class short name. There can be several of these
for the same course, in which case the program creates a separate identical course from each one for its own
use.

In the area <CourseVariation>:

<Name>H21</Name>
is recognised as the course variation name.

The program can also form the name by combining the course
name and the course variation name.

The program handles only numeric control codes, whose
maximum allowed value is 899. When reading a transfer file the program converts the codes
RR1, RR2, etc. into the codes 881, 882 etc. (this also applies to the codes RR10-RR19, which
become the codes 890-899).

If a letter code other than an RR control
or the letter 'V', 'J' or 'P' occurs in the middle of a course, the program interprets it as
a point related to a marked route or a map exchange where no punch is made, and skips
this point. The program then adds together the distances from the previous control to this
point and from this point to the next point. Using this
feature it is possible to increase the length of a leg even if there is no actual
marked route.

The letters 'V', 'J' and 'P' are used when the
punching order of the controls is partly free to choose (chapter 13.8).

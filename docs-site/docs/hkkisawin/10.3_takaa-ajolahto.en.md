# 10.3 Pursuit start

### 10.3 Pursuit start

The [class
data](2.2.1_sarjatietojen_muuttaminen.md)  must state that the stage is a
pursuit, so that all the functions described below work correctly.

The final results of a pursuit are normally calculated as the sum of
the result of the pursuit stage and the previous result, rounded
according to the rounding rule defined for the pursuit, i.e. usually down to whole seconds (for the biathlon procedure, see below).

Alternatively, the combined result of the pursuit can be defined
as the time from the start time of the first starter in the class to each entrant's finish.
This option does not work unless all entrants start in pursuit
fashion rather than in a mass start or at regular intervals. This procedure is selected
in the program's [basic settings](2.1_uuden_kilpailun_luominen.md)
, when desired.

In the pursuit stage, the timing precision that determines placings
should be set finer than what is written in the results,
because otherwise the program cannot give different placings to competitors
whose times are reported with the same precision. This may require changing the setting
before the pursuit stage competition. The change can also be made
after the competition, in which case it is needed only if such placing problems
occur. The change takes effect after the program is restarted.

A basic pursuit start is formed one class
at a time in the option
*Create pursuit start or reversed start order*. This is done in the results service mode of the previous stage.

The program normally determines the pursuit start times according to, among others,
the ski competition rules, first rounding the final results down to the nearest
second and calculating the start times from these times. The program rounds the previous
result in the same way when calculating the overall results after the pursuit stage.

The biathlon rules require a different
procedure, in which the start times are calculated from the differences in the results of the first stage,
rounding to the nearest second after calculating the difference. This often causes
a deviation of one second when the results are calculated. To prevent this from causing
errors, the program stores, when necessary, a one-second correction in the pursuit stage
data in a special correction field, which the program internally calls
*sakko* (penalty).

If desired, the winner's time can be subtracted from the earlier results,
so that the combined result of the first starter becomes his or her
time in the pursuit stage, but this subtraction usually does not need to be made;
it is better to keep all times in their original form, among other things for results lists containing the different stages.

# 1.4 Configuring the operating modes

### 1.4 Configuring the operating modes

The use of the program is controlled
by writing configuration files for each phase of operation. Preparation mode usually
does not require any additional definitions in the file, but definitions are almost always
needed when running the results service. The configuration file stores information
on, among other things, the data transfer connections the program uses to other computers and
the devices used, such as finish clocks and Emit readers.
In the future I will provide forms to support configuration, but
for now configuration files must be written with a text editor or
a similar editor in the program option *Files / Startup settings*. The appendix chapter of this manual
lists all available parameters. With a few exceptions they are
shared with ViestiMaali, and many of them are discussed
in more detail in the ViestiMaali manual (pdf file).

[Appendix 1](hkliite1.md) of this manual lists
all available parameters. Most of them are shared by
HkKisaWin and HkMaali. The list also states whether the parameter
can be defined with the configuration editor.

You can include comment lines in the configuration file
by starting the line with a slash '/' (common practice is to use two
slashes '//'). The configuration editor adds two lines to the file to delimit
the area it handles. Before the start line you can write, for example,
comments describing the purpose of the configuration file; below the end line
is the right place for parameters and comments edited with a text editor.
The configuration editor removes entries made between the start and end lines.
An old configuration file can be read into the configuration editor and
interpreted, after which the interpreted lines can be removed before updating the file
in the editor. Make sure that the interpretation does not leave out part of the line's
content, because the configuration editor does not handle all parameters
completely. If something necessary is left out, the more complete line must be
placed below the end line.

#### 1.4.1 Configuration editor

The configuration editor is opened by first selecting *Files / Startup settings* and clicking the
button found there. On the right side of the configuration editor there is a window for the
configuration file content being handled. Through the menu you can read an existing
configuration into it and finally save the new configuration to a file.
Separate menu commands let you interpret the file that was read and remove the
interpreted lines before the data defined in the configuration editor are written back
to the file (function *Update* ). If the data contain
start and end line markers, both interpretation and removal apply only to
the area between these lines.

The configuration editor contains several sub-pages:

- **Basic data**
  contains some basic data and some options used especially in
  fitness orienteering events

  - **Data transfer**
    contains the definitions of data transfer connections

    - **Timing**
      contains definitions concerning the handling of timing data and [the use of finish clocks and
      other timing devices](5.1_maalikellon_kaytto.md)
      . Timing based on Emit
      chips is, however, defined as an Emit function, and keyboard
      use in ViestiMaali in the program-specific settings of that program.

      - **Emit functions**
        contains the definitions both for punch checking and for [timing based on Emit chips (including
        emiTag)](6.10_mtr-_ja_emitag-laitteiden_ohjaus.md)
        .

        - **Printing**
          contains configuration definitions related to automatic output as well as
          the option to define a formatting file to be read when the program
          starts.

          - **ViestiMaali**
            contains some definitions related to the ViestiMaali
            user interface

Some of the definitions are made in tables on the
pages mentioned above. Some entries are best made by moving to the field to be edited,
clicking the right mouse button and selecting an option,
because correct operation of the program requires the entries to be made exactly
in the form the selection produces. For connections this applies to the columns
*Type, I/O, Messages* and *No
fwd.* and for Emit devices to the columns  *Device, Connection* and *Timing*
. The selection concerns, among other things, the type of device and the data transfer method.

Normally no entries are needed in the data transfer column *Messages*
. By adding one or more 3-character codes to the column you can
make the following selections

- Emt, EmO, EmI and EmV indicate that
  Emit records are also transferred, either in both directions, only
  sent, only received, or so that no other data are transferred
  at all

  - EVa indicates that precalculated
    control split times are sent. This mainly concerns transfer to an online service

    - Aik and AiV indicate that timing records
      are transferred; AiV indicates that other records are not transferred

      - ECd indicates that time records received by the program
        through data transfer are forwarded

        - Tie indicates that files can be transferred
          over the connection.

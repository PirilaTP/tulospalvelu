# 3.2 Reading entries from a file

### 3.2 Reading entries from a file

#### 3.2.1 Import from the orienteering IRMA system and the skiing Kilmo system

The program supports importing entries from files produced by the orienteering IRMA system
and the skiing Kilmo system. A file in a supported
format can be read in the option *Entries / Get from file* by selecting *Orienteering entry file* or *Skiing Kilmo entry file*. The program then
asks you to select the file and starts reading it.

If the orienteering entry file contains
extra lines that the program does not interpret as entrants, these can be skipped
by choosing to continue reading. If the program complains about a line that you want
to read, you can either stop reading, in which case the preceding lines have been read, or
continue and make a note of which lines were not read.

Reading a skiing Kilmo file stops at the first
erroneous item, such as an entry to a class missing from the competition.
In this case you must either delete KILP.DAT before the next reading attempt or
remove the lines already successfully read from the entry file, so that
competitors are not stored twice. Before a new reading attempt you must
also correct the entry file or the class definitions so that the data no longer
conflicts with the requirements of the competition.

In orienteering you must also take care of
the handling of club names, which is described in chapter 3.3.

#### 3.2.2 Import from csv files and data created with Excel

The program includes several ways of reading data
from csv files. The newest and in most cases most practical one is based on
the fields to be read being defined on the first line of the file using
identifiers like the following, which are hopefully understandable without further explanation:

No;KilpId;IntId;Piiri;Sukunimi;Etunimi;Arvo;Seura;Seuralyh;Yhdistys;Joukkue;Maa;Sarja;Sukup;Synt;Ikäsrj;ArvRyhmä;IlmLista;Piste1;Piste2;Piste3;Bib-1;Sarja-1;Badge-1;Laina-1;Badge2-1;Laina2-1;ArvLahto-1;TotLahto-1;Tulos-1;Tark-1;Sija-1;AmpSakko-1;Sakko-1;Rata-1;Selitys-1;PvPiste1-1;PvPiste2-1;Ennätys-1;Tavoite-1;Bib-2;Sarja-2;Badge-2;Laina-2;Badge2-2;Laina2-2;ArvLahto-2;TotLahto-2;Tulos-2;Tark-2;Sija-2;AmpSakko-2;Sakko-2;Rata-2;Selitys-2;PvPiste1-2;PvPiste2-2;Ennätys-2;Tavoite-2;VaTulos-1-1;VaTulos-1-2;VaTulos-2-1;VaTulos-2-2

The identifiers listed above correspond to a 2-stage
competition in both stages of which two split times are taken. The identifiers must
be written exactly right for the program to understand them. A list of the identifiers
can be created by writing data from the program to a file. This can be done once the competition
has been defined and opened for preparation, even if no competitors have been entered at all.

The columns listed above correspond directly to the file fields used by the
program. In addition, the column heading "Nimi" (name) can be used, in which case the program splits
the field into surname and first name, assuming that the data is in the form "Surname Firstname".

When new records are read into the program, the class
is the only mandatory column. Otherwise you only need to include the columns that contain data.

Essentially the same function is also available for supplementing and changing
previously created records. In this case the competitor's
base number (column "No") is a mandatory field, used to identify
the entrant. In addition, the columns whose data is changed are needed.
When supplementing data, you only need to include the competitors whose data is supplemented or changed.

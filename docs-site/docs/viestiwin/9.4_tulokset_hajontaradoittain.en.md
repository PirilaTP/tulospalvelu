# 9.4 Results by forked course

### 9.4 Results by forked course

Leg-specific results can be written
by forked course either for each leg separately or by combining into the same
results list all those in the class who ran the same course, regardless of
the leg.

Results by forked course are obtained by selecting
*By forking* under *Output restriction*. Under
*Legs to print* select either one leg or all legs;
in the former case select the leg as the data determining the order,
in the latter *All up to selected*. In addition you can keep
or remove the marking *Require team approval*, which determines whether
legs are included whose team's earlier leg has been disqualified.

If you also want those disqualified on their own leg
to be listed, the program must be given the parameter SÄILHYL, but even then the list includes only
those who obtained a time for the leg.

When the results of all legs are output
together, the program takes the codes from the competitor data and needs no other
instructions. When results are produced leg by leg, the file HAJONNAT.LST is needed
to tell which courses each leg of each class has. The structure of the file
HAJONNAT.LST is
as follows:

- each class
  corresponds to a block that starts with the line Sxxx, where xxx is the class
  name

  - within each
    class block there are leg-specific sub-blocks, which start with the line On, where n
    is the leg number

    - the leg-specific sub-blocks consist of lines, each containing
      one course code. In the course code, the positions of dummy characters
      contain a minus sign '-' and the actual codes appear as they are.

For example,
in a 3-leg relay using Motala forking, with
a three-character course code whose second character indicates the course, the block
corresponding to class 'A' is as follows:

```
S A
O 1
-1-
-2-
-3-
O 2
-1-
-2-
-3-
O 3
-1-
-2-
-3-
```

When the course-specific results are output, the program writes the code with its '-' characters in the heading.

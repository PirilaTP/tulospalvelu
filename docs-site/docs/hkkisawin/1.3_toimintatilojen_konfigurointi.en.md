# 1.4 Configuring the operating modes

### 1.4 Configuring the operating modes

The use of the program is controlled by writing configuration files for each
phase of operation. Preparation mode usually does not require any additional definitions in the file, but definitions
are almost always needed when running the results service.
The configuration file stores information on, among other things, the data transfer connections the program uses
to other computers and the devices used, such as
finish clocks and Emit readers. All of the most common configuration settings can be made with the configuration
editor described below, but configuration files can also be written with a text editor or
a similar editor in the program option *Files / Startup settings*
. Many less frequently used settings
can only be made by editing the configuration file with a text editor.

[Appendix
1](hkliite1.md) of this manual
lists all available parameters.
Most of them are common to HkKisaWin and HkMaali. The list also
tells whether a parameter can be defined with the configuration editor.

You can include comment lines in the configuration file
by starting a line with a slash '/' (the common practice is to use two
slashes '//'). The configuration editor adds two lines to the file to delimit
the area it handles. Before the start line you can write, for example,
comments describing the purpose of the configuration file; below the end line
is the right place for parameters and comments edited with a text
editor. The configuration editor removes entries made between the start and end
lines. An old configuration file can be read into the configuration editor and
interpreted, after which the interpreted lines can be removed before the file is updated
in the editor. You should make sure that
the interpretation does not drop any part of a line's content, because the configuration editor does not
handle all parameters completely. If something necessary is dropped, the
more complete line must be placed below the end line.

#### 1.4.1 Configuration editor

The configuration editor is opened by first selecting
*Files / Startup settings* and clicking the button found there.
On the right-hand side of the configuration editor there is a window for the
content of the configuration file being handled. Through the menu you can read an existing
configuration into it and finally save the new configuration to a file.
Separate menu commands let you interpret the file that was read and remove
the interpreted lines before the settings defined in the configuration editor are written back
to the file (function *Refresh*
). If
the data contains the start and end line markers, both interpretation and removal apply
only to the area between these lines.

The configuration editor contains several sub-pages:

- **Basic data**
  contains some basic settings as well as
  some options used particularly in fitness orienteering events

  - **Data transfer**
    contains the data transfer connection settings

    - **Timing**
      contains settings concerning the handling of timing data and [the use of finish clocks and
      other timing devices](5.1_maalikellon_kaytto.md)
      . Timing based on Emit chips is, however, defined as an Emit function, and keyboard use
      in HkMaali in that program's own special settings.

      - **Emit functions**
        contains the settings for both [punch checking and
        timing based on Emit chips (including emiTag)](6.10_mtr-_ja_emitag-laitteiden_ohjaus.md)
        .

        - **Printing**
          contains the configuration settings related to automatic output and the option to
          specify a formatting file to be read when the program starts.

          - **HKMaali**
            contains some
            settings related to the HkMaali user interface

Some of the settings are made in the tables on the pages
mentioned above. Some entries are best made by moving to the field to be edited,
clicking the right mouse button and selecting an option,
because the program works correctly only if the entries are made exactly
in the form the selection produces. For connections this applies to the columns
*Type, I/O, Messages* and *No sel.*, and for Emit devices to the
columns *Device, Connection* and *Timing*. The selection concerns, among other things, the device type and
the data transfer method.

Normally no entries are needed in the data transfer column *Messages*. By adding one or
more 3-character codes to the column, the following
choices can be made

- Emt, EmO, EmI and EmV indicate that
  Emit records are also transferred, either in both directions, only
  sent, only received, or so that no other data is transferred
  at all

  - EVa indicates that pre-calculated
    control split times are sent. This mainly applies to transfer to
    an online service

    - Aik and AiV indicate that timing records
      are transferred; AiV indicates that no other records are
      transferred

      - ECd indicates that time records received by the program
        via data transfer are forwarded
        onwards

        - Tie indicates that files can be transferred over
          the connection.

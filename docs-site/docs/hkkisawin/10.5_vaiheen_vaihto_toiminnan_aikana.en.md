# 10.5 Changing stage during operation

### 10.5 Changing stage during operation

The program allows the stage to be changed without closing and
restarting the program. This operation sends a message to the network, which causes
the stage to change on all computers in the network. The operation requires, however,
that none of the open data transfer queues contains outgoing messages,
so extra queues must first be closed using the menu. So that
the change does not stop at the network server, the server is the best place to make
the change.

The stage must not be changed while data is being edited on any computer in the
network.

In HkKisaWin the option for this operation is in the main menu item
*File* (*Change stage*). In HkMaali, first select Asetukset (Settings) and there
press the key 'W'.

This function makes, for example, the results service of a cross-country sprint
competition easier.

In a competition where the stage is intended to be changed during the event, it is advisable to give the configuration
parameter

vaihe=v

and make sure that the directory does not already contain the file
vaihevalinta.cfg, or if it does, that it contains
the parameter vaihe=x so that x refers to the stage to be started first. When
the file does not exist, the program starts in stage 1. If the parameter vaihe=v has not been given, you must make sure in some other way
that any restarts end up in the correct stage.
Starting in the wrong stage causes minor problems (data transfer does not
start, and the receiving computer gets a notice about this), but the situation
returns to normal when the restarted computer moves to the same stage as the rest of
the network. The error situation may, however, easily go unnoticed for
some time.

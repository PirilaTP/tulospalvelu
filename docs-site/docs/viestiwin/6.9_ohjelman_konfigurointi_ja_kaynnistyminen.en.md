# 6.5 Configuring and starting the program

### 6.5 Configuring and starting the program

For punch checking to be possible, competitor and
course data that are not contradictory are needed. For each competitor
there must therefore be information about the course, the course must be found in the course data, and for each control
one or more punch unit codes must be defined. When the program is started
in results service mode with the Emit functions enabled, the program checks the
compatibility of the data and points out both missing controls and missing
courses.

For each competitor the program first looks for a course whose name is the same
as the class name. If no such course is found, the course code recorded in the competitor's data
for that competition stage is used, if one has been stored,
and a course with that name is looked for. If no course is found this way either, the program writes
an error message to the file DATA\_ERR.TXT, which
can be opened for viewing when the check has finished.

The Emit functions are started when the program has been given
the startup parameter EMIT or any other
startup parameter related to the punch check function,
such as LUKIJA or LÄHEMIT.

More detailed information about the parameters used with the Emit functions
can be found in the PDF instructions for the Emit functions, which were written for the program
ViestiMaali (and its predecessors) but which also apply, where applicable,
to ViestiWin.

On the course data definition form you can check
the compatibility of the course data being edited by using the button *Check
definitions*. The program then compares the courses with the punch unit code definitions
and also with the competitor data of the running competition, if you are working
in results service mode. This helps prevent incorrect editing of the course data
during the event.

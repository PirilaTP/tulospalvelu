# 5.3  Tidtagning baserad på brickor

### 5.3  Tidtagning baserad på brickor

Tidtagning baserad på brickor används mest
i orientering, där brickan kan vara ett Emit-kort eller en emiTag. emiTag lämpar sig
också för längdskidåkning och andra grenar. Brickan kan också vara en
RFID-tagg, när lämplig RFID-utrustning finns tillgänglig. Nedan
behandlas främst tidtagning baserad på Emit-kort; användningen av programmet är
i stort sett identisk när emiTag-enheter används.

Att använda Emit-kortet för tidtagning förutsätter en så kallad
online-läsarstämpel, som registrerar stämplingen men inte gör att kortets klocka
stannar, så som läsarstämpeln som används i stämplingskontrollen gör. Uppgiften
kan gå från läsarstämpeln till resultatprogrammet på många olika vägar:

1. direkt via serieporten

   - som alternativet ovan men med seriekommunikationen
     förmedlad trådlöst med radiomodem

     - med TCP- eller UDP-protokollet från en terminalserver
       till vars serieport läsarstämpeln är ansluten

       - med Sune Johanssons SjBoxar, mellan vilka
         seriekommunikationen sker med en strömslinga

         - med samma dataöverföringsprotokoll som
           kommunikationen mellan programinstanser. Detta sker i allmänhet
           med UDP-protokollet, men även TCP-protokollet kan användas
           (meddelandeformatet har definierats för kommunikation med mitt program SendECodes)

           - med emiTag-enheter kan uppgiften också gå via Emits nätserver

I de fyra första fallen antas att
dataöverföringen är snabb, och tiden tas från datorns klocka när den identifierande
uppgiften har tagits emot. I allmänhet är den enda uppgift som fås det lästa kortets Emit-kod, men
med SjBox fås också den källkod som definierats för den serieport som
läsarstämpeln som gjorde avläsningen är ansluten till. I alternativ 5 och 6 fås förutom koden
även avläsningstidpunkten och en källkod som anger avläsningspunkten. I alternativ 1-3
kan en källkod kopplas till uppgiften baserat på den serieport eller annan
anslutning där uppgiften kommer in; för en terminalserver kan
terminalserverns portnummer användas här.

I alternativ 1-4 måste parametern LUKIJA läggas till i programmets konfigurationsfil
för varje direkt
serieportsanslutning samt för varje serieport på terminalservern vars uppgifter tas
emot. När anslutningen sker till datorns serieport har parametern formen

LUKIJAx=y

där x är förbindelsens nummer och
y anger att serieporten som används är COMy. En SjBox
ansluts i detta avseende på exakt samma sätt som en enskild läsare.

För en terminalserver som använder TCP-protokollet är motsvarande parameter

LUKIJAx=TCP:ip-osoite:portti

där ip-osoite är
terminalserverns ip-adress och portti är den ip-port som motsvarar
den serieport som används (i terminalservrar motsvaras varje serieport av en egen ip-port).

Vid tidtagning måste parametern

AIKALUKIJAx=VAINz

eller

AIKALUKIJAx=LÄHDEw

anges vid sidan av varje parameter LUKIJA.

I båda fallen måste värdet x vara detsamma som i parametern LUKIJA.
x kan dock utelämnas, och då gäller parametern alla LUKIJAx-parametrar.

z efter ordet VAIN kan vara

- ett siffervärde 0, 1, 2, ..
  upp till det högsta ordningsnumret för en mellantidspunkt som används. Värdet 0 avser målet. En parameter som anges så bestämmer den punkt som tiden registreras för

  - bokstaven A, varvid programmet
    söker den första mellantidspunkten som ännu saknar tid och registrerar tiden för den punkten

    - tecknet z kan saknas,
      varvid programmet använder filen lahdepisteet1.lst
      för att välja punkten. Detta lämpar sig främst för fall där SjBox används

I det senare alternativet är w
ett siffervärde som ges som källkod för den här anslutningen. Därefter
söker programmet punkten med hjälp av filen lahdepisteet1.lst.

Alternativ 5 tas i bruk genom att definiera den aktuella
dataöverföringsförbindelsen på samma sätt som andra dataöverföringsförbindelser. Förbindelsen ska definieras
som enbart inkommande. Dessutom måste parametern nedan anges (utan
den parametern hoppar programmet över meddelanden från tidtagningen)

YHTEYSAJAT

I det här fallet försöker programmet använda filen
lahdepisteet1.lst för att bestämma punkten med den
källkod som kommer som en del av tidtagningsmeddelandet.

Alternativ 6 behandlas inte närmare här. Instruktioner
för det finns separat. Det kan dock konstateras att även där används
filen lahdepisteet1.lst för att härleda punkten.

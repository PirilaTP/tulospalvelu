# 6.11 Editing punch data afterwards

### 6.11 Editing punch data afterwards

It is possible that a competitor's data are skipped
at punch checking or that the punch data are otherwise assigned incorrectly.
Such errors can be corrected afterwards by changing the punch data,
the competitor data or both, so that the competitor data and the file
EMITx.DAT contain consistent references to each other.

The competitor data normally contain the active
Emit code in the first Emit code field. The second
chip code field is normally used either to store earlier data or
for a second chip code in competitions where the competitor uses two chips.

The file EMITx.DAT always contains the code given by the original card,
but this field is not otherwise used; the active
code is in a different field, whose value can change. The record also contains the competitor's
number. For the punch checking data to be usable, the active
Emit code must be the same as that of the competitor whose number is in the number field of the punch checking data.

If the file EMITx.DAT contains several rows in which
the active Emit code and the competitor number are the same, the most recent of these is
used and the earlier ones are skipped. Therefore later rows must be changed
by setting both the competitor number and the active Emit code to zero.

In the most complicated cases the Emit data can be
edited with the program EmitEditor and the competitor data in HkKisaWin so
that compatibility is achieved. In many cases, however, the changes can be handled
more easily entirely with HkKisaWin.

A skipped Emit record can be activated in
HkKisaWin as follows (this should usually not be done during the event, but
only afterwards on one computer):

- On the punch checking form, enable the entrant search.

  - As the search filter, select *Show skipped
    too* or *Skipped only*. The latter is particularly suitable
    for finding possible skipped records when there is no more precise information about them in advance.

    - Find the skipped Emit record using the record sequence number and the buttons
      *Next* and *Previous* .

      - If the competitor to whom the record belongs is not known,
        this can often be found out with the help of the Emit code read. The competitor who has
        this Emit code can be searched for through the menu of the form *One entry*.
        When the competitor's number or name is known, you can move on to the next step.

        - Click the button *Change competitor, modify
          punch data, skip card*. Fetch the competitor by number or name.

          - If the box *Corresponding card read*
             is ticked, the competitor already has Emit data and this procedure must not
            be continued; if necessary, the earlier data must first be marked as skipped and only
            then can this procedure be continued.

            - When the competitor is selected and there is no obstacle to linking
              the data, you can click *Save competitor selection*.
              The data are now linked to each other using the Emit code the program judges most suitable.

Through the punch checking form option *Functions / Add
record for processing* it is possible to add records
to the punch checking data. This lets you, for example, create a record whose
punch times are then changed as desired based on an MTR printout. An existing
record, selected by competitor number or the valid Emit code, can be used as a model
for the added record. The record is created
with content corresponding to what a card readout produces, and after creating it the program moves
to the same functions as after a card readout. The competitor is selected
only at this stage. If you want the program to behave as when
the card used as the basis is read again, no new Emit code
needs to be given; otherwise it must be given. If no readout time is given, it is
that of the readout used as the basis, or in the course-based case the time
of adding.

Punch data can also be read from a file whose
structure is the same as that of the file EMITx.DAT, but interpreting them exactly as if they
were being read only at this stage. Such a file can be created, among other ways,
on the emiTag device handling form ([appendix 5](liite_5._emitag-laitteiden_kaytto.md)) and by reading the data
otherwise in the normal way but keeping the tick *Show new data*
off. In the same way,
data already handled once can be taken into new handling,
because in this function the program uses only the data read from the card and the information
on the readout time. All other data are recreated when the file is
read.

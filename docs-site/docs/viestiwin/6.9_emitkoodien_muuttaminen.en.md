# 6.9 Changing Emit codes

### 6.9 Changing Emit codes

When an Emit card is read at the punch check, the program always changes
the code stored in the competition data to a larger one, increasing the code by
1000000 as many times as needed for the code to differ from all previously stored codes,
i.e. by one million the first time the card is read, by 2 million the second time
it is read, and so on. In this way the program ensures that every piece of data
concerning a read card gets its own code, which also differs from all card
codes.

The program allows the same code to occur more than once only
within the same team. When a card is read, the program attaches the data to the team
in leg order, so the original code is always attached to the first leg using this
code that has not yet been processed at the
punch check.

In relays where Emit codes are not stored in advance but are recorded
when entering the changeover area, the same code is never held by more than one
competitor at any moment, even if the card is used several times in the same or in different
teams. Only in cases where a competitor who has already gone to the changeover gives the card
to another competitor without visiting the punch check in between could there be
an exception. In that case the program does not allow the card to be used again without the code
being changed for the previous competitor, which the program does automatically if
the performance is disqualified or did not finish.

Repeated use of the same card therefore does not normally cause
problems; instead, each performance has a different code after the competition. This
applies both to repeated use within the same team and to use in
different teams. In exceptional and fault situations (e.g. a very long interruption of data transfer),
however, problems can arise from repeated use of the same card, so
it always involves a small risk of confusion.

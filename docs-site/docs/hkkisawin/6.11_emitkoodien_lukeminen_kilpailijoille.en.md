# 6.11 Recording Emit codes for competitors, recording starters

### 6.11 Recording Emit codes for competitors

#### 6.11.1 Entering and editing codes from the keyboard

The HkKisaWin option *Entries / Enter Emit codes*
opens a form on which entering codes is easiest. In the form's
table you enter only the competitor's number and the new code. When a batch of codes has been
entered, save them with the button *Apply markings*.
In a multi-stage competition you can choose the stage whose code is changed. The default
is a change to the current stage (in preparation, stage 1)
and all later
stages, if any. With the drop-down selection you can choose whether the entry also applies to later stages or only to
one selected stage. At the same time you can add or remove rental card markings.

In addition to the most commonly used primary code, a second chip code can also be handled.

#### 6.11.2 Reading codes from cards

For example, the codes of rental cards can be read
for competitors in the program's preparation mode. This requires the program to be given the parameter

LUKIJA=xx

where xx indicates the serial port or other channel from which the data comes.

When this parameter has been given, the
*Entries* table option *Functions/Read emit codes* is available.
In this option you can further choose whether the cards read are marked
as rental cards. The option is available only when the table is in the mode
*Editing allowed* .

Before starting to read, it is usually advisable to enable
filtering requiring the chip code to be 0. This way only rows
that do not yet have a code are shown. When a card is read, its code goes to the selected
row for all stages of the competition.

You can get a list of the cards read if they have been
marked as rental cards, since start lists can be made including only rental card holders.

#### 6.11.3 Reading codes from a file

Emit codes can be read from a CSV-type file
with the option *Entries / Transfer of additional data*
following the procedures of that form.

#### 6.11.4 Recording starters and verifying the codes

When the program is given, in addition to the reader definition, the parameter

ESILUENTA

the program does not perform a punch check but only sets
the check code of a competitor previously marked as not started to *Open*,
i.e. the character '-'. If all competitors have been marked as not started before the competition,
you know that all competitors who are open have really
started. At the same time you can verify that the competitor's Emit card works
at least up to the start and that the competitor's Emit code matches the card in use.

This function is handled on the punch check screen, of which
the program shows only the necessary part, leaving out unnecessary data.

Alternatively, the corresponding function can be handled
on the timing screen when the timing point is defined as the start, but the competition does not
allow the start time to change based on the time taken (i.e. the start gate has not been
enabled in the competition's basic settings). The timing point can be defined as the start with the parameter

AIKALUKIJAx=VAINL

or with the point definition L
in the file lahdepisteet1.lst .

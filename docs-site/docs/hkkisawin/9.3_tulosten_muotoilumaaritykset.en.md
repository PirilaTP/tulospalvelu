# 9.3 Output formatting settings

### 9.3 Output formatting settings

The program handles the formatting of start lists and
results lists separately, based on solutions used in earlier separate programs (Arvonta
and Maali). Both kinds of formatting are however edited using
the same form component, and the program now saves all formatting settings
in a single XML file. Of the settings themselves, the font type choices and the top and bottom margins of
printer outputs are shared; other features are defined separately
for start lists and results lists.

The general principle of formatting is that for each item of data
you define its position on the line, the field length and whether the field is aligned left or
right. For printer outputs the position on the line is expressed in thousandths of the line length, and the field length in characters.
File outputs use monospaced characters and the position is given in characters. When
the field length is set to 0, the program does not
handle that field at all. In table-like HTML outputs the widths
also affect the relative widths of the cells, unless otherwise
selected.

The formatting definition of **start lists**
can be difficult to
interpret because of the large amount of data and the resulting lack of space
on the form. The program defines 7 different start list types,
each of which has its own columns. The columns also
consist of three groups, each of which has a column for each
list type. The first group gives the positions, the second the field
widths and the third the alignments. Each row has one data type; the bottom
rows however contain other settings, described below.

The start list types are

- Start list by class (alphabetical, number or
  start order)- Alphabetical start list of all competitors- Start list by club- Start list by start- For the first three there are separate versions
          containing the start times of either only one stage or all stages. The column
          name ending "-2" refers to the latter start lists

Below the rows for the different data types there are
rows defining the following parameters, each in its own column group.
Thus, for example, on the row *Dy/Tm/Dst*  the first 7 columns
concern writing the date, the next 7 writing the clock time and the rest
writing the distance on the title rows. The value 1 includes the data and 0 leaves it out. The time step and the margin
size are given in the same way as the field positions.

- Timep (time step): Staggering of the positions of the times of different stages in position units (only in multi-stage competitions)- Marg: Left margin in position units- Sv: Class always on a new page (1) or continued on the same page (0)- Dy: The date is written in the title data (1: yes, 0: no)- Tm: The clock time is written in the title data (1: yes, 0: no)- Dst: The distance is written in the title data (1: yes, 0: no)- Firstn: The name is written in the order "first name last name" (1: yes, 0: no)

There are five sets of settings for **results lists**, each of which is defined in its own table.

- Results of one stage or overall results only, for the printer

  - Combination of one stage's results and overall results, for the printer

    - Combination of all stages' results and overall results, for the printer

      - File results for devices other than
        mobile devices

        - HTML file results suitable for
          mobile devices

Column headings that differ from the program defaults can also be defined
for results lists. This makes it possible
to use fields for unusual purposes and indicate the content
with the heading. Headings other than column headings are common to all results list types and are defined on the first page of the formatting settings.

The number of lines used by a results list is determined by the actual
paper size and number of lines. For this the program uses data it requests
from the Windows printer driver. This way the program gets, among other things, information on whether
portrait or landscape paper is used. Changing the paper size, for example from A4
to A3, does not affect the font size, so any desired changes to font sizes and line spacing must be made separately on the first page of the formatting.

Formatting can be saved to a file and read
from a file using the options of the formatting form. Formatting can also be read
automatically at startup by giving the program the parameter MUOTOILU=tied.nimi .

**Results containing several stage results or split
times**

The formatting of printer outputs containing two or more different results
is defined in a different table from results
containing one result. For file outputs the same settings are used.
In both cases the settings for the additional results are at the bottom of the
table. The rows *Partial place* and *Partial result* give the settings
for the placing data and the result of the first additional result. Other results of the same type
are written at the intervals defined by the column *Step*.

Whether the primary result data should be included in the results list
and, if so, what is the most suitable position for it relative to the additional results,
depends on the content of the output being prepared.

When points are output primarily, the program writes them either
in the points field or in the result field. The points field is always used when
both times and points are output.

**Formatting of file outputs**

There are two sets of settings, which
offer exactly the same possibilities. The basic defaults of one are better suited
for small screens, among other things thanks to a larger font size and shorter texts.

File outputs have no separate settings for one
and several stages, but the program ignores fields that
are not suitable for the number of stages in question.

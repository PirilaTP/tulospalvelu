# 5.5  Handling split points

### 5.5  Handling split points

#### 5.5.1  Deducing the timing point from the file lahdepisteet.lst

The file lahdepisteet.lst is used when you want the point
corresponding to a time to be determined by the channel the time comes from, together with the competitor's
class and leg. This requires the competitor to be identified at timing
by a chip code. The program reads the file lahdepisteet.lst when the file exists and when
the program has been given the startup parameter LÄHDEPISTEET, YHTEYSAJAT, or AIKALUKIJA with the suffix LÄHDE.

The file lahdepisteet.lst
consists of lines of the type

```
sarja osuus piste koodit
```

sarja  is the class name or
the word KAIKKI, which means all classes not
mentioned by name in the file.    
osuus  is the leg
sequence number or the word 
KAIKKI, which means all
legs of the class concerned. 
  
piste  is the split point sequence number. Both
the letter M and the value 0
refer to the finish.  
koodit is
a list of one or more codes. Several consecutive codes can be expressed
by giving the lowest and highest value separated by a hyphen. The source code value can be
in the range 1-9999. It is advisable to avoid the smallest values in the range
that occur as the value x of the parameter LUKIJAx.

The file can contain, for example, the following lines for leg 1 of class H21

```
H21 1 M 25  
H21 1 1 31-36  
H21 1 2 41 42 43  
H21 1 3 1080  
H21 1 4 61 62  
H21 1 5 1080  
H21 1 6 100
```

The first line tells that source code 25 directs the time
to be the changeover time, codes 31-36 the time of the 1st split point, etc. Source code 1080
on its first occurrence makes the time the 3rd split time, and when the 3rd split time has already been recorded,
the 5th split time.

When the program has been given parameters that lead
to reading the file lahdepisteet.lst, the program also tries
to read the file lahdejonot.lst. The file lahdejonot.lst has exactly the same structure as
lahdepisteet.lst
. The only difference is that in place of the point
number or letter code there is the timing queue number. This makes it possible to split
the data corresponding to different legs and points into separate timing queues as well, based on the code
of the data source.

#### 5.5.2  Other settings related to deducing the split point

The parameter

```
PISTE=x   missä x on A, M tai numeroarvo
```

(where x is A, M or a numeric value) tells to which point the program attaches the time. M means finish/changeover, a numeric value the split point
sequence number and A automatic deduction
in order starting from the 1st split time. When all split times of the leg have been given,
the time goes to the changeover/finish. If the leg is also determined automatically,
recording the changeover time causes the following times to go to the next leg.

The same selections as with the parameter piste can be given or
changed on the ViestiMaali timing display with the keys *Alt-P*.

When the parameter

AIKALUKIJAx=VAINA

is used, the program selects as the point the first split time that does not
yet have a time. When the split points are filled, the time is not recorded for the changeover/finish unless
the parameter

VUOROMAALI

has been given, which forbids giving a time to the changeover/finish.

The determination of the point is also affected by
the parameter

SAMAPISTE=sama

where sama
gives in seconds the time
within which a repeated
time is assigned to the previous timing point. The default is 10
s.

Normally the program keeps the result of a given point
when new timing data arrive for the same point. This behaviour
can be overridden with the parameter

UUSINAIKA=n

which causes new timing data arriving within n
seconds of the saved time to replace the earlier one.
If =n is left out, the
default value of 120 s is used.

# 9.7 Automatic file output

### 9.7 Automatic file output

#### 9.7.1  Defining the outputs

Writing a single HTML results list file containing all classes
can be set to take place
automatically at fixed intervals. Output can be defined to take place either
as writing all final results to one file or so that each class is written
to its own file. When the latter method is used,
split times can also be output automatically. The results
produced can also be transferred immediately
to a web server.

Automatic writing can be started

- with the output form menu option *File / Automatic file output* or

  - using the parameter in the configuration file  
      
    HTML=väli  
      
    or  
      
    HTML=tied.nimi/väli  
      
    or  
      
    HTML=tied.nimi/väli/S  
      
    The first alternative requires additional settings
    to be given in the file AUTOFILE.lst. In the other
    alternatives tied.nimi is the name of the
    HTML file to be produced, väli the writing interval in seconds, and
    the S of the second alternative
    indicates that output is to class-specific files. When the word HTML is replaced by MHTML, the file is written using
    the formatting intended for mobile devices, unless the file AUTOFILE.lst changes this choice. /S can
    also be added to the first alternative, in which case it
    means that only the results of classes
    with changes are transferred.

In addition, the name and title of the page produced can be given with the parameters

```
HTMLTITLE=HTML_tiedoston_nimi 
HTMLOTS=HTML_tiedoston_otsikko
```

When outputting to class-specific files, the file name given with the parameter
HTML has no effect, and the output
concerns only the results themselves. The pages containing links to the files produced must therefore be prepared in advance.
This can be done by writing the results directly from the output form to separate files,
which can be done even if there are no results yet.

Automatic file output cannot be used at the same time as automatic printing
to a printer.

**Using the file
AUTOFILE.lst**

In the first alternative, and
when writing classes to separate files has been requested
and the competitor data directory contains the file AUTOFILE.LST, the program reads
the classes and points (finish or split point) to be output from that
file. In that case only the data requested in that file
is output. The file consists of lines of the form

```
 sarja piste tiedosto
```

or

 html=tiedosto piste
sarjaluettelo

 mhtml=tiedosto piste
sarjaluettelo

In the former alternative sarja (class)
is given in exactly the same form as in the class data. piste (point)
is given as a number indicating the sequence number of the split
point (0 refers to the finish). The file
name (tiedosto) may contain a directory path, which may be
necessary for further processing of the automatically output files.

In the latter alternative
html refers to a normal HTML file and mhtml to a mobile HTML file
(this setting overrides the choice in the configuration
file). sarjaluettelo (the class list) can be either
the word kaikki
, which
means all classes (not combination classes), or one or more
class names separated by spaces. Using both of the latter lines you can output
files suitable both
for larger screens and for mobile devices.
It is also possible to write several files, each
containing one or more
classes. A line containing a class list can be very
long (max. 1000 characters).

When
sending classes as separate files, the normal
practice is that only those classes are written that have had changes since the program
was started and the previous results list for the class was
written. By clearing the relevant tick, however, you can request that all classes
be written, which may be necessary, for example, after an interruption
in the program's operation.

#### 9.7.2 Transferring files to a server

Once the HTML file has been written, it can be sent
automatically to a web server with the help of a command file,
which is run as specified by the parameter `KOMENTO` after every output.
See [appendix A10](liite_10._komentotiedoston_automaattinen_suorittaminen.md);
section A10.2 contains a modern model based on `rsync`+SSH and a ready-made
`siirto.cmd` template.

Earlier versions of the program also had a built-in FTP/SFTP transfer,
which was defined on the form *File server settings* and saved
in the file `AutoJakelu.xml`, together with the corresponding `AUTOJAKELU` startup parameter.
The function has been removed (it required a commercial add-on), and
a command file as described in appendix A10 is used instead.

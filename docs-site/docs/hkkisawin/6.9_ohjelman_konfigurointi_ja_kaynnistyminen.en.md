# 6.9 Configuring and starting the program

### 6.9 Configuring and starting the program

For the punch check to be possible, competitor and
course data that are not contradictory are needed. For each competitor
you therefore need course information, the course must be found in the course data, and further each control must
have one or more punching unit codes defined. When the program is started
in results service mode with the Emit functions enabled, the program checks the
consistency of the data and warns about both missing controls and missing
courses.

For each competitor the program first looks for a course whose name is the same
as the class name. If no such course is found, the course code recorded in the competitor's data
for that stage is used, if one has been stored,
and a course with that name is searched for. If the course is still not found, the program writes
an error message to the file DATA\_ERR.TXT, which can be opened for viewing
after the check has finished. A course is however not required for a class marked
as a vacant class, nor for participant records marked as vacant.

The Emit functions are started when the program has been given
the startup parameter EMIT or any other
startup parameter related to the punch check function, such as
LUKIJA or LÄHEMIT.

More detailed information on the parameters used with the Emit functions
can be found in the PDF instructions for the Emit functions, written for the program
HkMaali (and its predecessors), but which apply where relevant
to HkKisaWin as well.

On the course data definition form you can check
the consistency of the course data being edited using the button
*Check definitions*. The program then compares the courses with the punching unit code definitions
and also with the competitor data of the ongoing competition when operating
in results service mode. This helps prevent incorrect editing of course data
during the competition.

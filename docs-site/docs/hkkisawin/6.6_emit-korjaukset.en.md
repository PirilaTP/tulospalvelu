# 6.6 Changes to punches and changing the competitor linked to them

### 6.6 Changes to punches and changing the competitor linked to them

The competitor linked to Emit punches can be changed
on the form *Emit changes*, which can be opened
with the punch check form button *Change competitor or edit
punch data*. Through the same form you can also make changes
to the data read from the card and to the stored readout time. Changes
to the punch data are however made in the table of the form *Emit data*, once changes
have first been allowed on the sub-page *Punch data changes*
of the change form.

The form *Emit changes* also opens
automatically when a card is read that has an unknown code or that is
faulty, giving the code 200 typical of faulty cards.

When you do not want to keep the data of the card read, you must
use the button *Mark card as skipped*
.

#### 6.6.1 Changing the competitor linked to the card

When the competitor's bib number is known, the
punch data can be moved to him or her simply by entering the number and accepting it. After the number
is entered, the name is shown. In addition, the box *Corresponding
card read* is ticked if punches have already been recorded for that competitor, which
should be taken into account in further actions. (The program also warns about this if
you proceed with saving despite this, and gives you the possibility to cancel
saving.) If the competitor's number is not known, you can allow a name search,
type the beginning of the name and complete the search by browsing with the buttons.

When the competitor linked to the card changes, the
competitor's Emit code also changes to match the card. In a multi-stage competition the change does not
apply to earlier stages, but it is also made for later stages unless
the option *Emit code changes also for future stages* has been deselected
in the punch check form menu option *Settings*.

In a situation where two competitors' cards
have been swapped and this is noticed after both have been read, the
error can be corrected by fetching one of the competitors on the form *Emit data*,
going to the form *Emit changes*, fetching the other
competitor there and using the button *Swap punches between
competitors*. After this you should verify for both that
the check marking and the final result are correct, and use the form
*Emit data* to correct them if necessary.

The option *Mark card as skipped* means
that the data of that card can no longer be viewed
in HkKisaWin or HkMaali. It can however be restored
after the competition with the program EmitEditor.

#### 6.6.2 Changes to punch data

On the second sub-page of the form *Emit changes*
you can change the readout time recorded for the card. This affects
the split times calculated in orienteering competitions, because the program determines the time of each
punch by comparing the times stored by the card at the punching moments with
the readout time.

One quite common reason for incorrect split times is
that reading the card at the punch check did not succeed on the first attempt,
combined with the fact that the readout time information left on the card is generally based
on the first reading attempt. This is most clearly true for old cards without a display;
cards with a display and the newest cards without a display behave
differently, but errors affecting split times can occur with all of them.
If the final results have been obtained correctly at the finish line, the split times can
be corrected using the button *Set the readout moment so that
the finish time definitions are consistent.*

The correction mentioned in the previous paragraph is not usually
correct when the readout time is too early relative to the finish; in that case
you should investigate carefully whether the error is in the readout time or only in the final result, and
make corrections only then.

Occasionally it has been observed that the card's clock has run
at double speed because of a small short circuit in the card. This
shows in the punch data in that all leg times are
doubled and the first controls typically appear to have been visited
before the competitor's start time. This error can be removed with the button
*Halve card times*.

Sometimes there is a need to change a time or code shown in the punch data
or to make other similar changes to the data. This can be done
on the form *Emit data,* once changes in the table
have been allowed by ticking the relevant box on the sub-page *Punch data
changes*
.

The effects of all the changes mentioned above can be
examined before making them permanent. They take effect only when
the button *Save changes.* has been used.

#### 6.6.3 Searching for deviations in split times

The button *Find
participant* on the form *Emit data* opens a search function in which you can select as the search criterion
*Finish-last ctrl.* When this option is selected for the first time, the
program moves to the punch data of accepted competitors in which the deviation is
most negative, i.e. where the final result is probably correct
and the split times are most wrong in the direction caused by a failed
first reading at the punch check. This error can usually be
corrected as described above in section 6.6.2. You should however
examine the data more closely to make sure that the explanation is correct and that the correction
will therefore lead to the correct result.

You can then browse the records by searching for the next one and
correct clearly negative deviations to zero. When the difference shown is between
-2 .. 2, it is usually only a matter of deviations due to rounding and possibly a small difference between clocks,
whose removal is unnecessary and does not necessarily
make the data more accurate than the original.

Next you can enter as the search value a clearly
positive number (typically a number between 3 and 5 is suitable, unless there has been
a significant difference between the clocks). The program then moves on to showing
errors in the opposite direction, which are rarer and whose causes are
varied. They should not be corrected without investigating their causes more closely, because
that could lose information needed to make the right correction.

When the largest positive deviations of accepted data
have been gone through, the program shows records related to disqualified and did-not-finish competitors,
whose calculated deviations are often large because of a missing
punch.

#### 6.6.4 Sending a previously unsent record separately

In some cases there may be Emit records that
are not sent automatically when they are created but which you want to send
later. This can happen when a record cannot be linked to a competitor immediately
but is skipped and later linked to a competitor. Such a record
is not sent automatically to data transfer when it is linked to the competitor,
but sending can be done by requesting it separately
in the punch check form menu option *Functions*.

A similar situation can occur in recreational orienteering,
where one computer is normally used only for registering starters, but
some finisher is also read on it. In such an event it is not worth continuously
transferring the data of participants registered as starters to another computer, but the finisher's
data should be transferred for the control split printouts. In that case you can give the starter registration computer
the parameter

LÄHEMITx=V

and
the finisher recording computer the parameter

LÄHEMITy=I

(x and y are the connection numbers).

When these parameters are used, the finish computer does not send any Emit data to data transfer, and
the start computer sends only data whose sending is requested through the punch check form
menu.

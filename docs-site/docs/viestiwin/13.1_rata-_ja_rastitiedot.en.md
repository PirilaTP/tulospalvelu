# 13.1 Course and control data

### 13.1 Course and control data

The option *Preparation /
Course data*
leads to the definition of course data and control punch codes and to the printing of these
data. This is handled as a separate preparation task, so
the program saves the data to files, from which they must be read separately
for use in the results service phase. When working in results service mode, however,
the course data of the active competition are automatically loaded for handling, and
they can be put into use after the file has been written with the button *Apply data*. Even during the results service it is
possible to view and edit other course data as well, when they are opened
separately and the button *Apply data* is not used.

Previously defined course data and punch codes must
be read for viewing using the buttons concerned or on the page *Transfer files*, where course data produced by other programs
(Condes, OCAD) can also be read.

When the data have been edited, they must first be saved
from the table to the program's memory and then separately to a file. This allows
the consistency of the data to be checked before they are written to the file.

The program's old way of storing and using course data
was based on two text files, RADAT.LST and LEIMAT.LST. The new storage method is based on a single
XML file radat.xml.
The file format used closely resembles
the earlier IOF standard 2.0.3 for course data, but with the following limitations
and exceptions:

- Each course variation is also an independent course.
  The program uses the name of the course variation as the course name.

  - The finish is usually treated as the last control, which must
    be given a numeric code and for which punch codes can also be defined.
    If there is no punching unit at the finish, the finish is nevertheless treated as a finish in accordance with
    the IOF standard.

    - Fields have been added to the file indicating the nature of
      the finish and the clearing advance (i.e. whether clearing takes place at the start moment or before
      it).

The buttons on the right side of the form
are used to read and write course data in the xml format of my results programs.
Reading and writing the old text file formats of my programs
is requested in the menu under the option *File*. On the tab discussed in chapter 13.4
you can handle both the program's own XML files and
several other file formats.

If the program's working directory contains a course
file in the new format, the program uses it in the results service; otherwise the program
reads the data in the old format, if they are found. It is therefore essential to
make sure that, for example, the file radat1.xml is exactly what you want to use
in the first or only stage of the competition.

In addition to the control and punch codes essential for the results service itself,
the course data include coordinate and distance data
and possibly the identification codes of the start and finish. These are needed if you want
to handle the map or use distance data, for example, in split time outputs.

# 2.1 Creating a new competition and defining its basic properties

### 2.1 Creating a new competition and defining its basic properties

When the program has started in basic mode, a new
competition can be created by clicking the button *Competition
creation and basic properties*. Here you can give the competition's
most essential properties and ask for the desired number of classes to be created.
To create the competition, select the desired folder either from existing
folders or by creating a new one. If the folder does not already contain the files `ilmoitt.cfg` and `laskenta.cfg` , the program creates empty files
with these names. If class data are also created when the competition is created, the
program saves the basic data and the created class data to the file `KilpSrj.xml`. The competition's basic data cannot be saved
without class data for at least one class.

Alternatively, you can create a competition based on an earlier
competition by reading its file `KilpSrj.xml`. After this, the competition's
title and other data can be changed in the option *Competition creation and basic properties* and saved
by accepting the selections made. Using an earlier competition as a basis can
substantially reduce the work of defining classes.

When the basic selections have been made and the class data exist,
the program can be started in preparation mode, and the program then creates a new empty
entrant file `kilp.dat`. Once
the entrant file exists, selections that
affect the structure of the file can no longer be changed, i.e. mainly the maximum number of legs
and the maximum number of split points. If you want to change these, the file
`kilp.dat`
must be deleted from the working folder. The number of active legs and
split points is often smaller than the stated maximums.

It is recommended not to change the maximums suggested by the program unless
larger values are needed, so that the resulting files are as similar as possible
across different
competitions.

When the sport or sport specification is changed, the program selects
the timing precision typical of the sport, the chip type used (in orienteering
Emit) and the typical penalty unit (in orienteering, 10 min, i.e. 600 s, for
the control route classes). These settings can be changed, but they revert
to the sport's defaults if the sport is changed afterwards. The program
does not operate on the basis of this information; the value given here only affects
the default value of the class-specific penalty unit
when classes are being defined.

The program lets you define four
precision-related settings:

- The time
  storage precision is most clearly chosen as the coarsest precision that allows
  results to be handled according to the rules, because there is no reason to use
  greater precision when the data are changed
  by hand.

  - The ranking precision is the highest precision
    that has an effect on the results themselves or the placings. Note that
    in a relay the placing is often determined by a very small difference, and the precision should
    be defined so that the placings come out right without changing the displayed
    result.

    - The time output precision is usually coarser than the ranking
      precision.

      - The split time precision does not affect the program itself, but
        online services may use a coarser precision for split times, which
        better corresponds to the actual precision with which split times are obtained.

The competition identifier code is essential when using
a MySQL database and also affects the default names of result files.

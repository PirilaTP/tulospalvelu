# 2.1 Creating a new competition and defining its basic properties

### 2.1 Creating a new competition and defining its basic properties

When the program has started in basic mode, a new
competition can be created by clicking the button *Competition
creation and basic properties*. Here you can specify the
most important properties of the competition and request the desired number of classes to be created.
To create the competition, select the desired folder either from existing
folders or by creating a new one. If the folder does not already contain the files `ilmoitt.cfg` and `laskenta.cfg` , the program creates empty files giving
them these names. If class data is also created when the competition is created, the
program saves the basic data and the created class data to the file `KilpSrj.xml`. The basic competition data cannot be saved
without the class data of at least one class.

Alternatively, a competition can be created on the basis of an earlier
competition by reading its file `KilpSrj.xml`. After this, the competition
title and other data can be changed in the option *Competition creation and basic properties* and saved
by accepting the selections made. Using an earlier competition as a basis may
substantially reduce the work of defining classes.

When the basic selections have been made and the class data exists,
the program can be started in preparation mode, and the program then creates a new empty
competitor file `kilp.dat`. Once
the competitor file exists, selections that
affect the structure of the file can no longer be changed, i.e. mainly the maximum number of competition stages
and the maximum number of split points. If you want to change these, the file
`kilp.dat` must be deleted from the working folder. The number of active
competition days can, however, be changed within the limits allowed by the maximum,
because this does not affect the file structure but only whether
all areas reserved for the different competition days are used.

The recommendation is not to change the maximum numbers suggested by the program, 2
stages and 10 split points, unless there is a direct need,
so that the resulting files would be as similar as possible across
different competitions. For a single-stage competition, enter this in the field *Number of days / stages*, but leave the maximum
at 2.

If the competition includes a **pursuit stage**,
what is said in [chapter
10.3](10.3_takaa-ajolahto.md)
must be taken into account.

A **cross-country sprint** usually has
3 or 4 stages. When cross-country sprint is selected as the sport of a new competition, the program sets
the number of stages to 4 and marks both the class and the bib number as changing
from one stage to another.

When the sport or its specification is changed, the program selects
the timing precision typical of the sport, the chip used (in orienteering
Emit), the typical penalty unit (in orienteering 10 min, i.e. 600 s, for
control-route classes), the use of a start gate, and the primary club data, which is
the abbreviation for orienteering and, for all other sports including fitness orienteering,
the long name. These settings can be changed, but they revert to the values typical of the sport
if the sport is changed
after this.

The program lets you define five
choices related to precision:

- The precision of stored times is clearest to
  set to the coarsest precision that allows the results to be handled according
  to the rules, because there is no reason to use greater precision when data is changed
  manually. When a start gate is used, greater precision may be needed
  than for determining placings, in order to avoid rounding errors contrary to the rules
  when results are calculated as the difference between the finish time and the start
  time.

  - The precision determining placings is
    the greatest precision that affects the results or
    placings themselves.

    - The output precision of times may be coarser than
      the precision determining placings. For example, in running events placings may
      be determined by tenths of a second, while only seconds are shown
      in the results lists.

      - The precision of split times does not affect the program itself, but
        online services may use a coarser precision for split times, which
        better corresponds to the real precision with which split times are obtained.

        - The pursuit start time rounding is often to whole seconds,
          even if the results of the first stage have been taken to a tenth of a second. In this case
          the total time is also calculated using the rounded time for the first
          stage.

The club data selection affects, among other things,
reading the file containing the entries. At many stages of use
you can separately choose whether abbreviations or long names are used for clubs.
Abbreviations should be selected mainly in orienteering, where
abbreviations are used in the entry data obtained from the IRMA system. This does not prevent
the use of long names, for example in results lists.

The competition identifier code is essential when using
a MySQL database and also affects the default names of output files.

In most competitions the class is always the same, but
in some cases a competitor's class can change from one stage to another. This
happens, for example, in cross-country sprint competitions, where each heat is a class of its own.
Correspondingly, a competitor's bib number can also change from one stage to another. The class or
bib number cannot change unless this is allowed in the competition settings.

The options concerning the combined result are described in [chapter 10](10.1_yhteista_monivaiheisille_kilpailuille.md)
.

When you exit the basic competition data definition
saving the changes, the program checks whether the last class has been defined
as a vacancy class. If not, the program suggests adding a vacancy class.
The added class is always named *VAKANTIT*.
It is advisable to accept the program's suggestion unless a class intended
as the vacancy class has already been defined. If such a class already exists, you should make sure in the class data definition that the class
has been marked as the vacancy class. If the last class is not the vacancy class, it is usually advisable
to change the order of the classes. A vacancy class is useful in many competition formats, and
adding one never does any harm. In orienteering a vacancy class is almost essential,
so that situations caused by unidentified and faulty Emit cards can be resolved without difficulty.

# 13.3 Control punching unit codes

### 13.3 Control punching unit codes

On this sub-page you change the codes of the punching units
at the controls. The punching units of each control are on the same row. Up to six
codes can be defined for one control.

The data is saved by first saving it to memory and
then to a file. The consistency of the definitions can be checked once the data
has been saved to memory.

The punching unit codes can be included
in the same XML file as the course data. In the program's results service mode they must be found in the same
file, unless an old-style text file is also used for the courses.

All punching unit codes can be removed with the button
*Clear table*, after which new codes can be read
from a simple text file, each line of which contains first the control code
and then one punching unit code. The same control code can appear on several
lines.

The punching unit codes 1 and 2 have a special meaning:

- punching unit code 1 means that any
  code is accepted as correct, but some punch is required at this point on the course- punching unit code 2 means that
    the whole control is skipped both in punch checking and in calculating split times.
    This is therefore suitable when a punching unit has stopped working during the
    competition.

# 3.1 Entering entries

### 3.1 Entering entries

Entry input is reached from a sub-option of the main menu item *Entries*.
The data shown on the entry input form can be selected on a second sub-page.
You can likewise choose whether a person database or a club list is used.
The most fundamental choice is whether the form is used to create new
records or to edit existing ones. In the latter
case the records to be edited have usually been created in the option *Add vacants*. Editing vacant places created in advance
is the best procedure when new entrants are added
in results service mode using data transfer between several
computers. Adding records is a good solution in the preparation phase.

Working on the form is easiest when you do not
ask to see data that is not meant to be changed from its default values. For example,
competitor numbers and bib numbers are irrelevant if they are to be
determined later in the draw.

#### 3.1.1 Using the person database and the club list

In entry input, entrants can be fetched from a person database
by name or by ID number (licence number). When
a search by ID code or name from the database is requested in the entry form options,
a database window opens asking you to select the database
file. The file used is a delimited text file, typically
a csv file. The program assumes that the data on each line is in the order
`id-koodi, sukunimi, etunimi, seura, maakoodi,
joukkue, sarja, rintanumero, sukupuoli, syntymävuosi, ikä` (ID code, surname, first name, club, country code, team, class, bib number, gender, year of birth, age).
The default separator is the semicolon. The separator can be changed in a menu option.

The second file format known to the program is the one used by the orienteering
IRMA system. It can be selected before reading the file
in the option *Settings*. Its fields are in the order
`id-koodi (lisenssinumero), etunimi, sukunimi,
sukupuoli, syntymävuosi, seuralyhenne, rankipisteet (desimaaliluku, jossa
desimaalierottimena piste), maksumerkintä, tunnistinkoodi (Emit)` (ID code (licence number), first name, surname, gender, year of birth, club abbreviation, ranking points (decimal number with a full stop as decimal separator), payment mark, chip code (Emit)).

The third supported file format is the file of the Finnish Ski Association,
which is usually supplied with the name LISENSSI.DAT. In it, text fields are
enclosed in quotation marks and the fields are in the order `Sportti-id (alussa 'T'), sarja, nimi (muodossa etunimi
sukunimi, mistä ohjelma löytää aina tai lähes aina oikein etunimet ja
sukunimen), seura, seuran numerokoodi (ohjelma ohittaa), lisenssin laji (ohjelma
ohittaa), FIS-koodi (ohjelma tallentaa kv. id:ksi)` (Sportti ID (starting with 'T'), class, name (in the form first name surname, from which the program always or almost always correctly finds the first names and surname), club, club number code (skipped by the program), licence type (skipped by the program), FIS code (stored by the program as the international ID)).

The program can also read csv files produced by the FIS software
and transfer FIS points from them for use in compiling the results
of a FIS competition (implementation still somewhat incomplete).

Fields can be left out at the end of a line. Two
consecutive separators in the middle of a line mean that the value of the field in that position
is missing.

The program menu lets you choose which fields
are shown. This does not affect the format required of the file.

When the database has been put into use, the program fetches
the requested record when *Enter* is pressed in the field defining the search (ID code, surname or
first name, which refines the name). When
the up or down arrow is pressed in the name field, the program moves to the person list,
where you can continue browsing with the arrow keys. When *Enter* is pressed
in the person list, the program transfers the data to the entry form.
The *Esc* key
returns to the previous field without transferring data. In the form
settings you can select which data the program fetches from the database.
With *Ctrl-Enter* you can go directly to
saving when all data is correct.

The club list is used in a very similar way
when a club name is typed in the club name field. When the abbreviation is
primary (usually in orienteering), the search is based on typing the abbreviation
in the abbreviation field. The file format of the club list used is also a delimited
text file, in which the fields are `piiri/aluekoodi
(numeroarvo), seuralyhenne ja seuran täysi nimi` (district/region code (numeric), club abbreviation and full club name). The club list can be
supplemented while entries are being entered, either automatically or using
the key combination *Ctrl-S* in the club name field.

When working on several computers with a data
transfer connection between them, additions to the club list are also transferred to the other
computers. This is possible only in results service mode, which on the other hand is not
the best environment for all preparation tasks and which requires that
competitors are given (preliminary) numbers when they are
entered.

#### Using a FIS file as the person database

FIS system data is usually taken into account only
after the entries have been saved ([chapter
9.2](9.2_tiedostotulostus.md)), but the following option is also available.

For the program to be able to write results in the format required for FIS competitions,
the entries must be recorded according to the FIS
competitor registers, giving the FIS codes as the international ID code and storing
the previous FIS points as ranking points. This is possible already when
entries are recorded, when competitors are picked from a csv file produced by the FIS
system. The points transferred are the points for normal distances,
so sprint points must be transferred separately. The required file can be
created from up-to-date data fetched from the FIS system using
the program *Fislist* distributed by FIS.

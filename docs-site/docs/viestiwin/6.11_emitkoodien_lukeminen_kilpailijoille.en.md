# 6.7 Reading Emit codes for competitors

### 6.7 Reading Emit codes for competitors

Emit codes can be transferred to competitors from a file
in the function *Transfer of additional data* . At the same time
you can also mark that the card is a rental card.

Information on rental cards can also be brought into punch checking
using the file lainaemit.lst, whose codes are reported
as rental cards without the information having to be entered in the competitor data. The file consists of lines,
each of which contains only one rental card code.

Reading
codes as competitors move to the start or changeover area can be handled with ViestiWin
when it has been given the startup parameter SISÄÄNLUENTA
and *Results service / Card readout (emit)* has then been selected from the menu.

In the card readout function, the competitor's data are first brought
onto the display either by reading a barcode in the prescribed format or by entering from the keyboard
the team number and leg. Then the Emit card is read and finally
the data are accepted with the Enter key. If you do not want to save the data,
the fields can be cleared with the Esc key.

If the previous competitor's Emit card has been read but the data have not yet been
saved or cancelled, the program does not take the next competitor for handling.
It gives the notice *Previous competitor's Emit card not yet
saved. Save or cancel it first.* in the same way whether
the next barcode was read into the barcode field or the acceptance field, or
the number and leg were entered from the keyboard. After the notice has been acknowledged, the previous
competitor and the card read remain selected and the focus returns to
the acceptance field. The data are saved with the Enter key or cancelled
with the Esc key, after which the next competitor can be read.

The program warns about situations where
the card is faulty (gives the code 200) or the competitor's code is already
assigned to another competitor. In both cases the card must be replaced.
In the latter case the solution can also be a change to the previous user's data
that frees the code. Such changes include disqualifying the performance and
changing the code in that competitor's data. The card should always
be freed at punch checking. A valid marking *disqualified, did not finish* or
*did not start* made without punch checking leads to the code being freed when the card
comes to card readout. The program carries out this freeing after giving a notice about
it.

The form's options let you choose whether the data are read
from a barcode or entered from the keyboard. Likewise you can choose
whether the program warns that the competitor's team or the competitor
themselves has a status marking for disqualification or not finishing, or that no
Emit code has yet been recorded for an earlier leg of the same
team.

When the program has been given the parameter LUENTALOKI, it writes to the file luentaloki.txt
information on all successful card readout events and on incomplete ones it has detected.

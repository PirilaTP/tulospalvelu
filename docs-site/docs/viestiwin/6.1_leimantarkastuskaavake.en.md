# 6.1 Using the punch check form

### 6.1 Using the punch check form

Punch checking requires that a
card reader is connected to the computer and the connection method is given to the program
with a parameter, usually of the form

LUKIJAx=y

where x is the reader's number
for the program and may also be omitted. The value y is
the serial port number, which for the computer's own serial port is usually 1,
but for a converter connected to a USB port usually higher, e.g. 5.
The port number can be found in the computer's Device Manager list under
*Ports*.

Punch checking also requires that the program
has access to the course data and the control punch unit data (chapter 13 of these instructions).

When the requirements described above are met,
you can go to punch checking with the selection *Results service /
Emit reading.* This form shows one competitor's punches and
information about the performance. When the performance is error-free, the data
according to the selections made is saved automatically and shown immediately on this form.
For an error-free performance the background colour of the form is white.
The form may also contain rows with a grey background; these
are not part of the performance but typically represent the card clearing
before the performance and extra punches during the event that do not belong to the course.

A new punch record is fully processed and shown only
if you have moved to the most recent data on the form. Otherwise a
button appears on the form; clicking it takes you to the processing. The
scroll bar above the punch table lets you browse
earlier punch records. You can also look them up with the button *Find participant*.

When the performance is not error-free, the table shows
various background colours and a disqualification proposal is made for the competitor. In the field
*Check* you must then select the option matching the performance (e.g.
*Disqualified*) and save the changes. In some cases the program does not
calculate the result, but calculation becomes possible as the data is
processed. The result can then be determined with the button *Calculate
result.*

On the punch check form you can
also change the competitor's course code. Changing the course is reflected immediately in the interpretation
of the punches. Other competitor data shown on the form can also be changed.

If no participant has the code of the card that was read,
the program attaches the data to a vacant record for the duration of the processing
(the program adds such a record if none exists beforehand). An auxiliary form
then appears automatically, on which you specify the competitor to whom the punches
belong. With the button *Change competitor or edit punch data*
you can open the same auxiliary form when the punches have been recorded for the
wrong competitor. With the auxiliary form you can move the punches to the correct
competitor, and you can also swap the punch data of two competitors.
The auxiliary form also has a second page on which you can edit the punch data.

Through the form's menus
you can, among other things,

- find the course that matches the punches. The program
  reports only one class or course, even if the punches would match several
  courses equally well. For a course to be reported, the punches must produce an
  approved
  performance. Of matching courses of different lengths, the program
  selects the one with the most controls, and of those with the same
  number of controls, the first in order.

  - take changed course data into use, which
    requires that the new defining files have been replaced in the
    competition folder before this,

    - affect the information shown to some extent, and print the
      punch data on a printer, or

      - start automatic printing of punch data
        containing errors.

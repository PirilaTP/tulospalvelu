# 16.1 The Transfer additional data form

### 16.1 The *Transfer additional data* form

The form can be used to transfer many kinds of data from a file
to the competitor data and from one competitor data field to another, as well as to
initialise fields either as empty or with a constant value.

The functions *Write to transfer file* and [Get from file](3.2_ilmoittautumisten_lukeminen_tiedostosta.md) are more practical
when several data items are handled at the same time.
This form is best suited to transferring a single data item.

#### 16.1.1 Transfer from a file to the competitor data

The file used is a text file whose content
can be divided into columns on the basis of separator characters. The separator can be
a single semicolon, tab or comma. A group of
one or more consecutive characters, all of which are
either spaces or tab characters, can also be used as a separator. If the interpretation is
unclear, it is advisable to use the auxiliary form described below in section
16.1.2.

On the form you must select

- The competitor data field used to find the correct
  record in the file. Most commonly the competitor's number
  in the competitor data (base number or the bib number of some stage) or
  the licence number (national or international) is used, but there are several
  other options too. Some of them select all entrants who have, for example, the same
  club.

  - When the data used can be stage-specific, you must
    also select which stage's data is used.- The field to which the data is transferred. There are
    currently 38 options, but the number may grow.

    - When the data is stored separately for each stage,
      you must select either one stage or all stages as the target.

      - When the transfer concerns a name, you can transfer either only
        the first name or the surname, or both from the same field, in which case options
        are offered for both orders.- If the transfer is carried out directly from the file
      without using the auxiliary form, you must select which column of the file contains
      the data compared with the identifying field and which contains the data to be stored
      in the competitor data. At the same time you must also select the field separator, whose options are
      described above.

      - When the data is a decimal number in the file, it must
        be converted into an integer, because the program stores only integers.
        The most commonly used multiplier is 1000, which is used for ranking points. In some
        cases the multiplier may be 10. Information on this is given where the data concerned
        is used. The program interprets as a decimal number a string that contains
        a full stop or a comma when it is read into a numeric field, such as ranking or other
        points.

When all selections have been made, use the button
*Select file and transfer data from file*, which first asks you to
select the file and then carries out the transfer. You should check immediately that
the data really has been transferred, because, for example, a wrong field separator prevents
the transfer from succeeding.

#### 16.1.2 Transfer using the auxiliary form for reviewing input data

Essentially the same result as in section 16.1.1 is obtained
more reliably and more clearly by opening the auxiliary form with the button *Open
form to review input data*. On this form the data is read from a file
into the upper text window, or moved into it using cut and paste
(i.e. Copy Paste). Then select

- the separator character or characters, as above,

  - the maximum number of columns to be interpreted,

    - whether quotation marks are used in the csv file,
      and

      - whether the text file has a heading row at the top that
        is skipped.

Then request the interpretation, and the program divides the data
into columns, showing the column number above and the row number on the left.
Any heading row is shown, but on a light grey background, like
the sequence numbers mentioned. These are not included in the data
transferred to the program. For a column, the number shown in the top row is used.

When the data is correct, select the columns to be used
and request the transfer with the button *Transfer
data from form table* on the additional data transfer form.

#### 16.1.3 Transferring data from one column to another

In many situations it is necessary to move some data item
from one column to another, for example when you want it in the results list but
the original field cannot be output. Here you select the identifying field and
the target field, as in section 16.1.1, but the data is copied into it
without using any file.

During the transfer, a numeric value can be increased or
decreased by a constant amount.

Similar operations can also be performed on
special forms, such as in the option *Copying club names and
classes* .

#### 16.1.4 Initialising a field

When *Initialise
field* is selected instead of an identifying field, the selected target field can be given a constant value. This is
most often used to remove content or restore a default value.

Initialisation can be restricted to some of the competitors
by using the area *Perform only with condition*. This way the operation can be
restricted to only one class or only to entrants who already have a certain
check code.

Some initialisation operations can be done more clearly in the option
*Reset or multiply results and version conversion* .

#### 16.1.5 Transferring data to a text file

The form can also perform the reverse of the operation
described in section 16.1.1, in which data is taken from one identifying field and one
content field and written as two columns to a csv-type
file. In this connection, an integer stored by the program can be converted
into a decimal number, which is needed mainly when the data concerns points,
which are usually presented as decimal numbers.

# 10.2 Cross-country sprint

### 10.2 Cross-country sprint

#### 10.2.1 Definitions before the competition

A cross-country
sprint competition is handled as a competition with 2–4 stages, the
first stage being the qualification (the so-called time trial) and the last the final. In between
there can be one or two heat stages (quarterfinal and semifinal). The best
prepared solution is one with 5 or 4 quarterfinals, correspondingly 6 or 4 competitors in each of the
semifinals, and A and B finals as the finals.

The competition must be created with the required number of
stages, i.e. four stages for a full-scale sprint. The competition must
be defined to use changing classes and also changing bib numbers,
unless bib numbers are kept unchanged. [Chapter 10.5](10.5_vaiheen_vaihto_toiminnan_aikana.md)
describes changing the competition stage without
restarting the program.

Each heat must be defined as a class of its own in the competition, and
the correct stage must be set as the competition stage of each heat. The qualification class is also the
base class of the competitors taking part in it, and through it the number of sprint stages is also defined.

All competitors are initially entered in the
qualification class, which remains permanently both their base class and their
qualification stage class. The classes of the other stages will change for those
who take part in these stages.

The implementation of each sprint class is described on a separate
form, which opens from the option *Ski sprint base class* on the
single-class definition form (see [chapter
2.2.4](2.2.4_hiihdon_sprintin_sarjat.md)
). This must be done when handling the
sprint base class, i.e. the qualification stage class. The form that opens defines the number of stages,
the number and size of the heats in the different stages, and the classes used for the
heats. When these definitions are made in the preparation phase, they are
available during the competition when heats are formed.

In a sprint, bib numbers
usually change when moving from the qualification to the next stage. The same numbers cannot
be used in different classes in the same stage, but the same number can belong to
one competitor in the qualification and to another in later stages. It is therefore
a good idea to define stage-specific starting bib numbers for each heat stage
that correspond to the number range used (e.g. always 1 for women and
101 for men). The program always uses the number given for
the first of the classes selected to be formed. The starting number defined for the first stage
is used in the qualification draw, and the starting number of the second
stage is used as a suggestion for renumbering
when forming the first heat stage. If renumbering is not
wanted, the starting number of the second stage classes must be set to 0. The starting point of numbering
can be changed when heats are formed on the basis of the qualification, but
to avoid errors it is best done in the class definitions.

If it has not been selected in the competition's basic properties
that the bib number can change from one stage to another, the program does
not allow numbers to be changed when the sprint heat stages are formed.

Since numbers are not changed after the first heat
stage, the starting numbers entered in the class data of the
third
and fourth stages have no significance. It is clearest
to set the starting number of these stages to 0.

The start times of the different classes should be entered approximately correctly for all heats,
preferably too early rather than too late, so that the results
give the placings correctly even if the start time is not corrected.

In connection with the draw or as a separate
operation, it is advisable to number the competitors for the later heats
in a number range that is not used in the competition itself. The program suggests numbers
that are the base number increased by 2000. Accepting this suggestion
may make things easier later. As a separate operation, the groundwork can be
done
on the form *Ski sprint transfers*
  before forming the heats.

If competitors use the same
bib numbers in the heat stages as in the qualification, you must make sure that the numbers really are
the same and have not been increased e.g. by 2000 in connection with the draw or later.

It is also
a good idea to mark all competitors in advance for the later stages
with the mark *Vacant*, because this keeps competitors not taking part in the heats
most reliably out of, among other things, the start lists, but allows last-minute
corrections better than the mark *Absent* . This mark can be made in the function
for transferring additional data. When a competitor is accepted to a later stage, the
mark changes automatically
to open.

#### 10.2.2 Forming the heats

When a competition stage has been completed, go, in the mode of that
stage, to the option *Ski sprint transfers* and
select the transfer to be made. In this option the program moves the competitors who
qualified to the relevant class (heat) for the stage being formed, and
gives each of them a bib number determined by the qualification placing and the
start time of the relevant heat. At the same time the program enters in the data of the finished stage
the mark Q or q for those who qualified, and when forming the final only for those who
reached the A final. In the competitor's data, the field *Course* receives the number corresponding
to the ranking within the heat, indicating the order in which the competitors may choose
their start position in their heat.

The letter Q
or q indicating qualification is written in the results lists in the same field as the disqualification mark, if this
field has been selected for output.

Provided that the follow-on stages
have been defined for the sprint base classes in the class data, all the necessary selections are normally
set correctly by selecting just the base class.

A ski sprint transfer
is always done one base class at a time, so that the source classes are the heats of the finished
stage of one class and the classes to be formed are the heats of the next stage.

If an error occurs in the marking, the marking must be undone
by restoring the previous entries. In this case the increment must be the same as originally, or differ
in such a way that there will certainly be no number overlaps. If the restoration is not made,
some competitor who should be left out may be wrongly included and get a number
that overlaps with that of a correct
entrant. The program allows partial restoration of data,
but normally it is advisable to restore all the selectable data.

If the number of heats differs from the model of 5 heats, 12
competitors to the semifinal and 6 to each final, the desired numbers must be changed in the number fields. The number of entrants determined by time comparison
must also be given (the total number advancing on time from the heats to the semifinal, and those
selected on time for the A final). The program assumes that when heats of 6 competitors are used,
2 advance to the semifinal on time and 2 to the A final.

In a small sprint competition, competitors can be
moved from the qualification directly to the semifinals. If
not everybody advances from the semifinals to the finals, the heat size must be given according to
those advancing to the A final. The program does not transfer those who did not finish. If no B final is skied,
the number of heats to be formed is set to 1, in which case the transfer is made only for the A final. The program moves
to the B final all those who took part in the semifinals without abandoning
and did not reach the A final.

#### 10.2.3 Recording the start time of a heat

When the start time of a heat is obtained from the finish clock, the easiest
way to record it for the entrants is to press the key S in the bib number field and select the class name corresponding to the heat.

#### 10.2.4 Two-stage sprint

When a sprint has only two stages, i.e. competitors go from the qualification
directly to the final, use the option *Directly qualification->final*,
select one qualification class at a time as the source class and
the corresponding final classes as the classes to be formed. The number selected on time
is set to zero. The program then places the best in the A final, the next ones
in the B final, and so on. In addition, the program enters in the qualification stage field
*Qual* the letter R, S, T, .. so that those who reached the A final
are marked R, those who reached the B final S, and so on. The program uses this
entry when compiling the overall results list of the class.

The letter R, S, .. is written
in the results lists in the same field as the disqualification mark, if this field has been
selected for output.

#### 10.2.5 Sprint in which the number of stages varies from class to class

When the number of stages varies from class to class, one of the following methods must be used.

- Arrange the competition so that each class can be
  run in consecutive stages, leaving out stages at
  the beginning or the end. In this case, either the qualification or the final is in a different stage for different
  classes, which may require switching back and forth between stages during the
  competition.

  - Skip one or two stages during the
    competition by creating, for example, a semifinal directly from the qualification or
    a final directly from the quarterfinal. Before the final results lists
    are compiled, the stages must be made consecutive by moving data from one stage
    to another, copying the stage following the omitted stage over it and then
    possibly the stage following that over the one just copied. Data is copied from one stage to another in the option
    *Preparation / Moving times, numbers and stage*. On the form you
    only need to select the source and target stages and the classes
    the copying applies to. The data of the source stage does not change in the copying. Finally
    make sure that the classes are marked as present in the class data
    as they are after the transfer, and that the extra stages have been left
    out.

#### 10.2.6 Final results

The results of a sprint competition can be written both by stage and as a list in the ranking order
of the whole competition. The latter contains either only the placings or the heats
and results of all stages. The latter option is currently available only
as HTML output.

# 13.2 Courses

### 13.2 Courses

#### 13.2.1 Basic functions

The course to be viewed is selected from the drop-down list or
created as a completely new one.

Creating a new course starts by typing its name
and selecting add course from the options that appear. The option
appears when you start typing a name in the field  *Course (new) name.*

The name typed in the field *Course (new) name*
can be used to rename an existing course or it can be
used as the name of a new course. A similar existing course can be used as the basis
for a new course by first bringing that course onto the display, giving a new name and
selecting *Add course*. A new course is always placed
last in the file. A course name may be at most 11 characters long and it
must consist of capital letters, digits and such
special characters as cannot act as separators. Forbidden characters include the full stop,
the comma and the semicolon.

Each added or changed course must be stored
in memory using the button *Store edited course in
memory* before moving on to the next course. If it has not
been stored, the program asks whether the data should be saved. It is, however, clearer to
save using the button.

Usually class names are used as course names. If
the course name is not a class name, the course used by the competitor
must be given in the competitor's data. This option is used, among other things, in mass start competitions
with forking, i.e. where not all entrants in the same class visit the controls
in the same order.

In addition to the control codes, the course definition includes
the selection of the start advance and timing method to be used.

Control codes must be numeric values in the range 1 .. 899
(see chapters 13.4 and 13.8 on the use of the letter codes V, J, P and RR).

#### 13.2.2 Start advance

- *Reset advance
  varies* means that the start time is taken to be the start time
  according to the draw, so that the moment the card was cleared does not affect the result.- *Reset at start time*
    means that the start time is determined by the moment the card was cleared, and the result
    is determined entirely from the card data.- *Fixed reset advance*
      means that the start takes place the given number of seconds after
      clearing.

The advance definitions shown on the display can be copied
to all courses using the menu option *Course functions / Copy course reset advance to all
courses*.

#### 13.2.3 Finish line punching unit or code

- *Punching unit on finish line (not
  online)* is selected when there is a punching unit on the finish line that is used
  for timing so that the finish time is determined at punch checking
  by subtracting from the readout moment the time, according to the card data, from the finish line
  punch to the readout. This is the most common procedure in national competitions and
  almost the only one in fitness events. When this option is selected, the finish must
  be given a control code and the finish must be included in the controls of the course. The finish control
  code can be added to all courses at once, as described
  below.- *Online punching unit
    on finish line* is selected when there is a punching unit on the finish line that is used
    for online timing with a computer connected to it. An
    additional option *Punch check calculates missing
    results automatically* is then available, which should usually be selected so that punch checking
    works automatically as a backup for timing. The online timing time does not
    change at punch checking, so the option is suitable alongside online timing
    to produce a time when no online time has been received. When this option is selected, the
    finish must be given a control code and the finish must be included in the controls of the course.
    The finish control code can be added to all courses at once, as described
    below.- *No punching unit at finish*
      is selected when the time is in no case calculated from punches, not even
      in the event of online timing disruptions. In this case the finish can be given a
      separate code in the course data, but the program has no use for it. The distance from the last
      control to the finish should then be entered according to reality.

**Note 1:**
The course data are exactly the same in the first option and in the second
option when *Punch check calculates
missing results automatically* has also been selected. Because the course data are the same,
the program will afterwards show the option *Punching unit on finish
line (not online),* even though the selection was made according to the second option.
This is normal behaviour and gives no reason to change the selections.

**Note 2:**
In the third option a field appears in which the distance
from the last control to the finish is entered. The value of this field must be 0 if there is
a "last control" on the finish line. In that case the finish point does not need to be defined
in any other way either.

The separate option *Punch check calculates missing
results automatically* should be selected in the second option, unless you specifically want
punch checking not to calculate the time automatically when it is missing
at the moment of punch checking. Automatic calculation can be dispensed with
in connection with online timing when you carefully monitor that everyone gets a time
and when you always want a notice about gaps in online timing. When using this option,
it is recommended to also use the parameter VAADIAIKA so that this notice is given.

The finish mode definitions shown on the display
can be copied to all courses using the menu option *Course functions / Copy course finish options to all
courses*

The finish control code is part of the course data. It can
be added separately to each course or added to all courses using
the menu option *Course functions / Add finish control code (numeric) to all
courses*. This option adds the same code to all
courses. If the code is already the last code of the course, a second code is not added.
When making this addition the program moves the distance defined in the file
from the last control to the finish to be the distance to this added control and sets
the distance from this control to the finish to zero, as it actually is.

See section 13.4 on combining course data
that is in several parts.

The **start code** and the **finish code** can also be saved as part of the course data in cases where the finish is not otherwise
included in the course. These data are not needed in punch checking or in split time
calculation; their only use during the results service concerns
the map display, whose interpretation can be helped by showing the start and finish
points. If there is a punching unit at the finish, the finish code should be left out
so that two items are not drawn on top of each other in the map image.

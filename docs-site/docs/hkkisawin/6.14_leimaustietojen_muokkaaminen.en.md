# 6.14 Editing punch data afterwards

### 6.14 Editing punch data afterwards

#### Editing existing data

It is possible that a competitor's data is skipped
during the punch check or that punch data is otherwise assigned incorrectly.
Such errors can be corrected afterwards by changing the punch data,
the competitor data or both, so that the competitor data and the file
EMITx.DAT contain consistent references to each other.

The competitor data normally contains the active
Emit code in the first Emit code field. The second
chip code field is normally used either to store earlier data or
for second chip codes in competitions where a competitor uses two chips.

The file EMITx.DAT always contains the code given by the original card,
but this field is not otherwise used; the active
code is in a different field, whose value can change. The record also contains the competitor's
number. For the punch check data to be usable, the active
Emit code must be the same as that of the competitor whose number is in the number field of the punch check data.

If the file EMITx.DAT contains several rows on which
the active Emit code and the competitor number are the same, the latest of these is
used and the earlier ones are skipped. Later rows must therefore be changed
by setting both the competitor number and the active Emit code to zero.

In the most complex cases the Emit data can be
edited with the program EmitEditor and the competitor data in HkKisaWin so
that consistency is achieved. In many cases, however, the changes can be handled
more easily entirely with HkKisaWin.

#### Activating skipped data

A skipped Emit record can be activated in
HkKisaWin as follows (it is usually not advisable to do this during the event, but
only afterwards on one computer):

- On the punch check form, enable the competitor search.

  - As the search filter, select *Show skipped
    too* or *Skipped only*. The latter is particularly suitable
    for finding possible skipped records when there is no more detailed information about them in advance.

    - Find the skipped Emit record using the record's sequence number and the buttons
      *Next* and *Previous*.

      - If the competitor to whom the record belongs is not known,
        this can often be found out from the Emit code read. The competitor who has
        this Emit code can be searched for through the menu of the form *One entry*.
        Once the competitor's number or name is known, you can move on to the next step.

        - Click the button *Change competitor, modify
          punch data, skip card*. Search for the competitor by number or name.

          - If the box *Corresponding card read*
            is ticked, the competitor already has Emit data and this procedure must not
            be continued; instead, if necessary, the earlier data must first be marked as skipped and only
            then this procedure continued.

            - When the competitor has been selected and there is nothing preventing
              the data from being linked, you can click *Save competitor selection*.
              The data has now been linked using the Emit code the program judges most suitable.

#### Adding a new record

Through the punch check form option *Functions / Add
record for processing* it is
possible to add records to the punch check data. This way you can, for example,
create a record whose punch times are then changed
as required based on an MTR printout. As a model for the added record
you can use some earlier record, selected by
the competitor number or the current Emit code (i.e. not
by the original code if the code has changed). The record is created
with content corresponding to what a card readout produces, and after creation the program moves
to the same functions as after a card readout. The competitor is selected
only at this stage. If you want the program to behave as
when the model card is read again, no new Emit code
needs to be given; otherwise it must be given. If the readout time is not given, it is
that of the model readout, or in the course-based case the time of
adding.

#### Transferring data from another file

Punch data can also be read from a file whose
structure is the same as that of the file EMITx.DAT, interpreting it however as if it
were being read only at this point. Such a file can be created e.g.
on the MTR or emiTag device handling form ([Chapter 6.10](6.10_mtr-_ja_emitag-laitteiden_ohjaus.md),
[appendix 9](liite_9._emitag-laitteiden_kaytto.md)) and by reading the data
in an otherwise normal way but keeping the tick *Show new data*
off. In the same way
data that has already been processed once can be taken for reprocessing,
since in this function the program uses only the data read from the card and the
readout time. All other data is recreated when the file
is read.
